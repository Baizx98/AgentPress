# 今日概览

截至北京时间 2026 年 11 月 15 日上午，本期没有将周末缺少新论文误写成“今日集中发布”。筛选范围以 11 月 9—12 日首次公开或修订的论文为主，关注三条有实质机制的主线：跨模型 KV 表征转换、Agent 的文件化记忆训练与证据追溯，以及长时程 AI 基础设施优化的评测。以下均明确标出首次公开时间，作者实验结果不等于生产部署保证。

- **BridgeKV** 把 prefill 与 decode 的模型选择解耦，不只是把同一模型的两个阶段放到不同 GPU。
- **CAMP-II** 将普通文件操作和持久工作区变为 Agent 记忆策略的训练接口。
- **WikiTrace** 使压缩后的经验条目能回溯原始执行证据，减少错误记忆带来的退化。
- **Infrathon** 说明 AI Infra 优化 Agent 的排序可能随评测时间预算改变，短基准难以覆盖长期收益。

## 核心论文与技术报告

## 1. BridgeKV：跨模型 KV 翻译让大模型 Prefill、小模型 Decode 成为可能

**来源与时间**：Payman Behnam 等，2026-11-09 首次提交，[arXiv:2611.11761](https://arxiv.org/abs/2611.11761)。这是近七天论文，不是 11 月 15 日新发布。

**问题**：传统 PD 分离通常仍由同一个模型完成两阶段计算。Prefill 是相对计算密集的阶段，Decode 的逐 token 重复访存更敏感。若直接换用小模型解码，来自大模型的 KV 无法按形状和语义直接消费。

**机制**：BridgeKV 让大模型执行 prefill，使用轻量 KV-stitching 模块将其缓存转换为同家族小模型的缓存布局。模块使用局部跨层混合、分别针对 K/V 的非线性映射；冻结两侧模型，先学习缓存对齐与下一 token 预测，再可选择加入低秩适配器。

**证据**：作者在六组模型配对、五个数据集共 30 个设置中，报告优于同等可训练参数预算的微调小模型基线；质量差距最多缩小 80%。A40 上 8B→1B 配对的请求速度约为全程 8B 的 3 倍。论文对 70B→1B 给出的最高 33.86 倍速度和 27.5 倍能耗下降**来自服务模拟**，不能当成实测集群结果。

**限制与价值**：转换模块需要训练，质量受模型家族、任务和缓存表示差异影响。它把“KV Cache 是否可跨模型复用”从存储格式问题推进为表征映射问题，也意味着未来异构 PD 系统可能需要同时考虑翻译成本、缓存传输与质量约束。

## 2. CAMP-II：把文件系统操作训练成 Agent 的记忆行为

**来源与时间**：Lirui Luo 等，2026-11-10 v1、2026-11-12 v2，[arXiv:2611.14009](https://arxiv.org/abs/2611.14009)。本期关注 11 月 12 日修订版，不声称修订具体改变了哪一项实验。

**问题**：长任务会跨越上下文窗口，Agent 必须决定什么时候记录、修改、搜索和恢复记忆。若蒸馏训练依赖模型从未见过的专用记忆工具，教师难以指导，学生也很少采样到有效记忆操作。

**机制**：作者提出 CAMG-II，在 Shop、Coding、AutoResearch、General、Visual 五类环境中提供 Bash 和跨上下文替换仍持久存在的工作区。CAMP-II 使用完全异步的 on-policy distillation，让学生利用预训练阶段已熟悉的文件操作，学习何时写文件、修改文件、检索文件和复用历史状态。

**证据**：论文报告在 CAMG-II 上取得最强 OPD 基线 **2.97 倍的增益**，并在 Terminal-Bench 2.1 和 SWE-Bench Pro V2 上观察到成功率改善。这里的“2.97 倍”指作者定义的增益，而非所有任务成功率直接乘以 2.97。论文提供[项目主页](https://liruiluo.github.io/)；本文未将项目主页存在等同于完整代码和数据已开放。

**限制与价值**：五类训练环境的收益不能自动外推至多用户并发、共享文件一致性或恶意工具输出。值得关注的是，文件操作既是 Agent 的执行接口，也是可训练的记忆控制接口；持久化工作区可能成为比专用 memory API 更通用的训练与系统抽象。

## 3. WikiTrace：Agent 记忆不应脱离产生它的执行证据

**来源与时间**：Yukyeong Lee 等，2026-11-10 首次公开，[arXiv:2611.14320](https://arxiv.org/abs/2611.14320)。论文注明处于 ACL Rolling Review 审稿中，不能描述为已录用。

**问题**：Agent 从成功或失败轨迹提炼“经验教训”，但压缩后的文字可能错误、缺乏适用条件，或者被后续任务误读。缺少原始轨迹时，使用者难以核查记忆的真实性。

**机制**：WikiTrace 将精炼 insight、解释任务成功或失败原因的摘要以及原始 trajectory 通过链接组织起来。新任务先读取简短经验；当经验细节不足、相互冲突或来自失败任务时，Agent 通过终端工具逐层追溯证据并修正判断。

**证据**：作者在五个 Agent benchmark 中报告优于现有记忆方法和仅提供相同 insights 的对照，并减少 memory-induced degradation。论文明确给出[代码链接](https://github.com/)入口；具体仓库地址应以论文内链接为准，不能由 GitHub 域名推断发布完整度。

**限制与价值**：保留原始轨迹会增加存储与检索成本；跨任务轨迹还涉及权限和敏感信息隔离。它提供了一个重要区分：记忆命中率高，不等于记忆可靠；长期记忆系统需要来源追溯、证据核验与可纠错更新。

## 4. Infrathon：长时程 AI Infra 优化不能只测短时间成绩

**来源与时间**：Zhengyu Hu 等，2026-11-09 首次公开，[arXiv:2611.11995](https://arxiv.org/abs/2611.11995)。

**问题**：Coding Agent 优化内核、缓存编码器或其他 AI 基础设施时，真正的任务常涉及多轮实验、编译、测试和回归。几分钟的评测可能无法代表长时间优化能力。

**机制**：Infrathon 构建不同层次的真实 AI Infra 优化任务，以长时间预算运行 Agent，并分析完整轨迹中的探索、验证与停止行为。

**证据**：论文评测六个模型、150 次运行，每次最高 24 小时，总计超过 10,000 GPU 小时；其中 135 次运行在预算后半段继续获得改进。作者还报告一个 KV 视频生成编码任务中，Agent 将平均压缩率由人工基线的 6.82% 提升至 19.86%。这些结果属于指定任务与评测环境，不能概括为 Agent 已普遍超越系统工程师。

**限制与价值**：长时评测昂贵，模型排序随预算变化，测试不可靠、任务违规与过早终止均会干扰结论。研究 Agent 驱动的系统优化时，需要将测试可信度、预算、回滚和重复实验纳入 benchmark，而不是只看最终最佳数字。

# 前沿概念和技术

## 跨模型 KV Cache 翻译

BridgeKV 所讨论的不是跨实例搬运同一个模型的 KV，而是不同模型内部表征之间的转换。前者主要解决缓存身份、传输和布局，后者还需要解决语义对齐与预测质量。将两者混为“KV 可直接共享”会高估工程成熟度。

## 文件化记忆与证据链接记忆

CAMP-II 关注**如何学习记忆操作**：何时写、读、改和复用文件。WikiTrace 关注**如何验证记忆内容**：经验来自什么轨迹、在什么条件下有效。两者互补，但目前没有证据表明二者结合后必然取得额外性能收益。面向长任务的状态管理至少需要区分可编辑工作区、压缩经验和原始执行轨迹。

# 深度分析

## 对大模型推理与存储优化的启发

**第一，PD 解耦的优化空间正在从资源调度扩展到模型异构。** BridgeKV 表明阶段间可通过可训练转换层连接，但真实收益取决于大模型 prefill、KV 翻译、小模型 decode、跨设备传输及模型质量的联合预算。模拟器的极高倍数加速需要在真实负载和部署条件下复验。

**第二，Agent memory 应按状态语义而非统一文本缓存管理。** CAMP-II 的工作区文件具有读写与版本演进特征；WikiTrace 的原始轨迹更接近可审计证据，压缩 insight 则是可快速检索的派生状态。不同状态在保留期限、更新频率、共享权限和恢复路径上并不相同。将它们一律当作普通 prefix cache，可能丢失关键依赖关系。

**第三，系统优化 benchmark 应把时间和验证成本计入指标。** Infrathon 中大量运行在后半程继续改善，提示短时评测可能低估迭代搜索收益；但较长预算也增加误测试和无效探索的机会。合理的评价至少应报告质量随时间曲线、复现实验、任务约束遵守情况和资源消耗。

# 今夜白的观察

这批论文的共同点，不是简单增加缓存容量或 Agent 上下文长度，而是重新定义“状态能否被正确使用”。BridgeKV 研究状态能否跨模型解释，CAMP-II 研究状态操作能否成为模型习得的策略，WikiTrace 研究状态是否具备可追溯的证据链，Infrathon 则研究长期操作是否真正产生可验证收益。由此可以提出一个尚待实证的判断：未来 AI 系统的状态管理接口，除了保存与读取，还需要明确转换、版本、来源、验证与成本语义。当前这些工作各自在受限环境内提供证据，尚不能证明统一的系统方案已成熟。
