# 今日概览

截至北京时间 2026 年 11 月 12 日上午，最值得关注的技术主线是：**KV 复用的正确性边界、Agent 会话缓存的稳定性、推测解码的联合资源分配，以及跨节点注意力和 MoE 通信路径重构**。本文优先选取 11 月 9—10 日首次提交、11 日出现在 arXiv 分类更新中的一手论文；以下“今日”指本期发现和核验，并不冒充所有论文均在 12 日首次公开。

1. 跨模型版本复用 KV 可能保留任务效用，却不等价于新模型原生推理；系统必须同时衡量正确率与行为偏差。
2. Agent 的 prefix cache 可能出现由短时突发诱发的持久性能塌陷，单纯增加卸载层不一定解决。
3. 推测解码不仅要优化接受率，还要联合控制 draft 与 verify 计算预算；训练目标也开始直接对齐实际接受长度。
4. 分布式 decode 正在探索将模型权重归属与请求 KV 归属分离；MoE 通信则针对小 batch 固定开销进行协议级改造。
5. 隐状态 probe 能改进有限审核预算下的错误发现，但跨任务泛化仍然有限。

# 重点进展

以下八篇论文集中讨论缓存状态、在线调度与通信路径，按系统瓶颈而非论文平台排列。

## 核心论文与技术报告

## 1. 跨版本 KV 复用：任务效用与行为一致性是两件事

**来源**：[Can KV Cache Be Reused Across Model Updates? A DeepSeek-V4-Flash Case Study](https://arxiv.org/abs/2611.14051)，Zhikun Tao 等，arXiv v1 提交于 **11 月 10 日**。

**问题与机制。** 模型权重更新后，旧 KV 是否还能安全使用？作者研究四组模型更新，重点分析 DeepSeek-V4-Flash 到 Flash-0731 的直接缓存复用，并提出 Functional Cache Divergence，通过下一 token 分布比较复用缓存与新版本原生缓存的差异。该指标弥补仅检查问答正确率的不足。

**证据。** 在已有源缓存的条件下，三个较长前缀 QA 基准的 TTFT 中位加速为 **2.10—5.08 倍**；但不同版本的检索准确率差异很大。自然文本续写的行为一致性相对更好，而单 token 检索任务随着前缀变长更容易出现兼容性下降。即使首 token 相同，也不能保证完整答案和停止行为相同。

**限制与价值。** 加速以源缓存已经存在为前提；结论不能外推为所有模型更新均可安全复用。值得关注的是跨版本缓存的准入机制需要同时考虑任务质量、分布偏差与重算代价，而不能只看哈希和命中率。

## 2. ForeSpark：同时分配 draft 与 verification 预算

**来源**：[ForeSpark](https://arxiv.org/abs/2611.13442)，Jaeyong Song 等，**11 月 10 日**提交。

**问题。** 并行 drafter 一次前向生成完整候选块，但高负载下大量候选根本不会被验证。作者报告 drafting 最多占一个 step 时间的 **40%**，其中大部分计算被浪费。仅控制 verify 长度无法减少已发生的 draft 开销。

**机制。** Work-Conserving Speculation 使用上下文特征在 draft 前预测不同候选长度的接受情况，通过轻量全局排序联合分配每个请求的 draft 和 verify 长度，再将剩余验证预算投入更有希望的候选 token。作者在 vLLM 中实现原型。

**结果与边界。** 在论文的匹配生成速率条件下，相比 DSpark 吞吐最高 **1.77 倍**，相比自回归解码最高 **2.49 倍**；在延迟 SLO 下可支持的请求率最高为 DSpark 的 **1.51 倍**。这些是作者实验结果，不代表所有 batch 和硬件均有同等收益。核心启发是把 speculative decoding 当作跨请求资源调度问题，而非单请求接受率优化。

## 3. Agent prefix cache 的亚稳态：突发结束，性能仍可能无法恢复

**来源**：[Bursts That Outlast Themselves](https://arxiv.org/abs/2611.13412)，Wen Huang、Jack Liu，**11 月 10 日**提交。

**问题。** Agent 每轮上下文增长，prefix 命中时只需增量 prefill，未命中则可能重算 **10K—40K** token。作者发现短时请求突发会让活跃会话增多、KV 工作集超出容量，命中率下降又进一步拖慢服务，形成正反馈。

**证据。** 在 12 组成对实验中，9 组出现突发后持续退化，命中率约 **10%**、吞吐约减半，后续 **70 分钟** backlog 仍增长；无突发对照没有相同退化。论文还报告 Qwen3-32B、SWE-bench 形态 Agent trace 和 SGLang 上的相关现象。单纯限制新请求在 7 次塌陷实验中只恢复 1 次；按照活跃会话容量约束暂停部分已接纳会话则全部恢复。CPU offload 延迟但未消除塌陷。

**限制与价值。** 结果受工作集、会话到达和缓存容量影响，不能简单概括为 prefix caching 有害。它提示 Agent serving 的控制变量应包含**驻留会话工作集**，而不仅是请求队列长度和 GPU 利用率。

## 4. Decode Token Parallelism：分离模型权重与 KV 的节点归属

**来源**：[Decode Token Parallelism](https://arxiv.org/abs/2611.13293)，Susav Shrestha 等，**11 月 9 日**提交。

**机制。** TKNP 将单份模型按层块分布于节点；当前层的投影和 MLP 在负责该层的节点对完整 batch 计算，而各节点对自己拥有的请求在本地 KV 上执行 attention。跨节点移动的是当前 token activation，不必在跨节点执行 attention partial result 合并，也不需要每个节点复制全模型。

**证据。** vLLM 原型在最多 **64 张 H100**、Llama 3.1 405B 和 Nemotron-4 340B 上评估；长上下文高并发场景的完成吞吐相比 DCP 最高 **1.7 倍**、相比数据并行最高 **2.06 倍**。

**限制与价值。** 这不是无通信设计：层间 activation 仍要跨节点移动，且收益依赖网络拓扑、batch 和长上下文占比。关键抽象是将“模型参数在哪里”与“某请求的 KV 在哪里”解耦。

## 5. NVLinkOneSided：针对小 batch MoE 通信固定开销

**来源**：[One-Sided Expert-Parallel All-to-All](https://arxiv.org/abs/2611.13188)，Bo Li 等，**11 月 9 日**提交。

**机制。** EP 的 dispatch/combine 通常需要两次 all-to-all。NVLinkOneSided 让源 rank 将 token 直接推送到目标 GPU 的 rank-major buffer，避免前置元数据交换；grouped GEMM 原地读取，减少 per-expert 拷贝。Fence 与 Sentinel 两种同步协议分别面向吞吐和低延迟。

**证据。** Blackwell 单 NVLink 域内，dispatch/combine 比 DeepEP 快 **1.2—3.0 倍**，MoE 层相比 DeepEP+DeepGEMM 最高 **2.4 倍**；在每 GPU 最多 128 token 的测试中也有竞争力。

**限制与价值。** 不能将单 NVLink 域的结果直接推广到跨机 RDMA。工作强调小 batch decode 中协议固定成本可能比纯带宽更重要。

## 6. SHADOWPREFILL：Agent 跨模型路由的缓存预热

**来源**：[SHADOWPREFILL](https://arxiv.org/abs/2611.13176)，Haoran Qiu 等，**11 月 9 日**提交。

**问题。** Agent 逐步选择不同模型时，切换会破坏模型专属 prefix cache 的复用。作者报告含平均 **63K token** 上下文的生产 coding-agent trace；模型切换后 prefix hit rate 从同模型调用的 **80—89%** 降到 **44—65%**，切换调用耗时增至 **1.5—3.2 倍**。

**机制。** 利用未选中模型实例的空闲容量和在途请求的 SLO slack，提前对潜在下一模型执行 shadow prefill；必要时把 shadow KV 放到主机内存，预热未完成则回退到冷切换。

**证据与限制。** 在论文所用 24 组模型对、五套 Agent benchmark 中，切换调用延迟降低 **8.5—21.4%**，LLM 调用延迟降低 **3.7—17.7%**，路由 token 成本降低 **22.5—46.1%**，单请求能耗增加 **0.4%**。结果依赖可利用的空闲算力、路由可预测性与 SLO slack；并非无成本预取。

## 7. REAL Loss：让 drafter 训练直接对齐真实接受长度

**来源**：[REAL Loss](https://arxiv.org/abs/2611.14399)，Yu Tian，**11 月 10 日**提交。

**机制。** 传统交叉熵、KL 或一些 block-level surrogate 不等价于真实 Expected Acceptance Length（EAL）。作者指出按目标模型续写分布平均后续接受情况，会忽略实际验证路径由先前接受 token 决定的条件分布，产生可能反转梯度方向的协方差缺口。REAL 用路径权重构造无偏估计，并通过 Rao–Blackwellization 降低方差。

**证据与限制。** 在 Qwen3.6-35B-A3B target、Domino drafter 的受控比较中，论文报告 REAL 在九个任务子集、五个随机种子上优于若干对照损失；公开了参考 loss 实现。这里是特定训练设置下的接受长度改善，不能直接等同于生产吞吐加速。它将算法目标与 serving 的实际接受路径联系起来。

## 8. Auditing the Judge：隐层信号能否改善有限预算审核

**来源**：[Auditing the Judge](https://arxiv.org/abs/2611.14323)，Mayank Gulati、Gerhard Wunder，**11 月 10 日**提交。

**机制。** 作者比较模型自身 verdict token 连续分数与从 attention-head activation 训练的监督式正确性 probe，重点衡量固定审核预算下能找出多少错误，而不是只报告总体 AUROC。

**证据。** 三个 7—12B 开源模型在 GSM8K、MATH 上，5% 审核预算下 probe 在六个模型-数据集组合中额外发现 **1.3—22.5 个百分点**错误，中位数 **7.4**；跨数据集迁移时 probe AUROC 均下降。10% routing 下，probe 优于等成本随机分配，但只在较弱 judge 的设置中优于 judge-guided routing。

**限制与价值。** 这是监督、域内的审核预算分配证据，并非通用可靠的内部置信度。系统层面值得关注按风险分配复核计算，而不是把隐藏激活直接视为可信的真值。

# 前沿概念和技术

**功能性缓存偏差（Functional Cache Divergence）**将缓存兼容性从“是否命中”扩展为“复用状态产生的预测分布是否偏离原生推理”。它不是缓存一致性的通用标准，而是本期跨版本 KV 论文提出的具体评估工具。

**亚稳态 Agent serving（metastable serving）**描述缓存命中、服务速率、活跃会话工作集之间的反馈：外部短时扰动结束后，系统仍可能停留在低吞吐状态。与普通短时排队延迟不同，其关键在于状态容量与会话生存期共同决定恢复难度。

**工作守恒推测（work-conserving speculation）**把 draft 和 verification 都视为受限预算；优化对象不再只是接受 token 数，而是扣除浪费计算后在服务负载下的有效吞吐。与 REAL 的训练目标互补，但两篇论文没有证明组合使用后的增益。

# 深度分析

下面从缓存语义、Agent 生命周期和计算通信协同三个角度提炼这些工作的共同系统问题。

## 对大模型推理与存储优化的启发

首先，**缓存身份与缓存效用需要分开定义**。跨版本 KV 的实验表明，命中不保证行为一致；模型版本、层结构、任务类型和输出偏差都可能成为复用准入条件。其次，Agent workload 的 session locality 不只是提高命中率的机会，也是容量失控和正反馈退化的来源，因此 admission、suspension、offload 和恢复应联合考虑。再次，长上下文并行与 MoE 通信的论文共同表明，数据移动的**对象、拓扑和同步协议**与传输字节数同样重要。最后，推测解码的调度与训练目标都应面向端到端 serving 指标，避免以离线 acceptance 指标替代线上 goodput 和 SLO。

# 今夜白的观察

本期最鲜明的变化不是又出现了某个更大的模型，而是研究开始重新审视系统中的**状态语义与反馈机制**。旧 KV 能否复用、Agent 会话何时必须暂停、下一模型是否值得预热、draft 是否值得生成，这些都不是单一 kernel 的问题，而是涉及正确性、生命周期与资源预算的在线决策。值得继续追踪的证据包括：跨版本缓存的质量阈值是否能迁移到不同模型族；Agent 缓存亚稳态是否在更广泛真实 trace 中重现；以及新推测解码方法在高并发、多租户和异构硬件上的 SLO 收益。
