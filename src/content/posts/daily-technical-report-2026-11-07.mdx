## 今日概览

本期以 2026 年 11 月 1—6 日首次公开的一手材料为依据。最值得关注的主线是：Agent 记忆正在从“把历史塞回上下文”走向显式状态、可执行意图和参数化记忆的组合；同时，GPU Kernel 的 Agent 自动生成开始引入形式化验证。推理框架方面，跨实例 KV 的索引与租约正确性成为实际工程问题。以下论文均为近期预印本，不能视作独立复现实验。

## 核心论文与技术报告

### 1. LARK：用 Lean 证明 Agent 生成的 GPU Kernel

**新增点与来源。** Zixi Zhang 等于 11 月 1 日公开 [LARK](https://arxiv.org/abs/2611.02028)。其问题并非再提高代码生成成功率，而是解决“测试通过是否意味着 Kernel 正确”的证据缺口。

**核心机制。** 系统预先为目标语言的算子和 GPU 机器行为建立 Lean 4 语义，再将候选 Kernel 分割为可验证片段，由 Agent 生成片段级证明，最终组合为整体等价性证明。证明目标覆盖精确算术下的功能与内存行为，与基于随机输入的测试有根本区别。

**实验与限制。** 作者报告，在 KernelCraft 上，GLM 5.3 验证 12 个 Level-1 Kernel 中的 10 个，Opus 5.5 验证 5 个 Level-2 Kernel；抽样 10 个生产 Kernel，9 个通过验证，另一个发现数据竞争。该结果依赖形式语义正确性及精确算术假设，不能直接推断浮点误差、所有硬件微架构行为都已得到覆盖。

**研究价值。** 对自动生成 FlashAttention、量化、MoE 等 GPU Kernel 的系统而言，验证可能从“运行大量测试”向“证明核心语义并辅以性能测量”转变。

### 2. Agent Memory as Rate-Limited Filtering：长上下文不等于正确状态

**新增点。** Tianhao Guo 与 Chongyao Guo 于 11 月 2 日发布[论文](https://arxiv.org/abs/2611.02361)，构造具有授权、撤销、过期和时间顺序约束的可执行事件历史，比较直接读取日志和显式维护状态。

**方法与证据。** 作者将 Agent 记忆建模为递归过滤：每次事件更新有限状态，查询只需读取与当前决策有关的状态。论文报告，7B—32B 开放模型直接读取 256 个事件时准确率降至 48%—55%，而读取当前状态的部分 32B 推理模型达到 96%—98%；模型解析事件、规则执行状态更新的混合过滤器在 256 事件下取得 80%—89%。

**边界。** 实验围绕可定义规则和状态键的合成任务，不能简单外推至开放域语义记忆；解析错误、规则变更和状态冲突仍是系统风险。

**意义。** 对长期 Agent，状态写入时的依赖更新与读取时的全文检索是两种不同的计算路径，前者可能显著减少上下文长度及历史顺序推理负担。

### 3. Pro-Memory：把未来意图从过去事实中分离

Yuanchen Bei 等在 11 月 3 日公开 [Prospective Memory for Proactive LLM Agents](https://arxiv.org/abs/2611.05731)。传统记忆主要回答“过去发生了什么”，但主动 Agent 还需判断“某项承诺何时应该执行”。

**机制。** Pro-Memory 保存待执行目标、支持证据与触发条件；新观察到来时分别判断目标相关性、行动时机与是否已完成，并把完成事件沉淀为经验记忆。作者在延迟意图和开放式主动协助两类基准中报告了跨模型的性能改善，同时限制不必要干预；摘要未给出统一提升幅度，因此不在此杜撰数值。

**局限与启示。** 其收益取决于触发条件和外部事件是否可观测。Agent runtime 可能需要独立于上下文窗口的 pending-intent 状态、触发器及可恢复的执行记录。

### 4. Route to Remember：参数记忆与文本记忆之间的路由

Zeyu Fang 等于 11 月 3 日发布 [Route to Remember](https://arxiv.org/abs/2611.05636)，并标注为 NeurIPS 2026 PALM Workshop 工作。论文尝试把用户事实通过 on-policy self-distillation 内化为权重记忆，同时使用 verify-then-regenerate 路由，让权重记忆和文本检索各自处理更适合的问题。

作者在 HaluMem 上报告其方法达到或超过部分全文上下文与检索基线，并减少每次查询的输入 token；具体收益依赖数据和训练设置，不能理解为权重更新普遍优于可审计文本存储。系统层面的关键问题是：参数记忆更新成本、事实遗忘与版本回滚如何和外部记忆共存。

### 5. Reglos：记忆演化之外，Harness 也要接受独立评估

Sen Yang 等于 11 月 4 日公开 [Reglos](https://arxiv.org/abs/2611.06049)。系统在追加式用户记录中维护偏好变更与遗忘，同时让 Coding Agent 从失败轨迹提出 Harness 补丁，再由不同模型家族的 critic 检查基准投机，冻结 Harness 后由固定评估器筛选后续补丁。

论文报告，使用 Qwen3.8-27B 时在 PersonaMem-v2 和 LongMemEval-S 上分别取得 61.3% 与 84.0%。这些是作者在指定基准和 backbone 下的结果，不代表所有长期交互环境的普适性能。该工作的重要贡献是把“记忆内容是否更新正确”和“处理记忆的程序是否真的泛化”区分为两个评估对象。

## 开源项目的重要新闻

### vLLM Router：外部 KV 索引服务进入设计讨论

11 月 5 日创建的 [Router PR #528](https://github.com/vllm-project/router/pull/528) 以 WIP 形式探索 Mooncake Conductor 作为外部 KV-cache index provider。它涉及路由阶段的缓存位置发现，而不是直接改动 Attention Kernel。**当前是未合并的设计与实现讨论，不是已发布能力**；还需验证索引新鲜度、节点失效和查找延迟是否抵消命中收益。

### vLLM：NIXL 远端 KV 租约过期的读取保护

11 月 5 日创建的 [vLLM PR #66011](https://github.com/vllm-project/vllm/pull/66011) 针对生产者 KV lease 已过期时仍可能发起远端 prefill 读取的边界，拟拒绝无效读取。该变更影响跨实例 KV connector 的状态有效性，不是吞吐优化结果。PR 状态以仓库实时页面为准，不能将提案当成已发布修复。

## 前沿概念和技术

**递归状态过滤**强调历史事件写入时即计算状态转换；**前瞻性记忆**强调未来目标与触发时机；**权重—文本混合记忆**强调按查询选择不同的知识载体。这三种机制分别解决状态正确性、行动时机和访问成本，并非同一种“记忆压缩”。LARK 则提出另一条独立主线：Agent 生成系统代码时，可信执行需要形式化语义而非仅靠测试集通过率。

## 对大模型推理与存储优化的启发

首先，Agent 记忆不应统一视为可召回文本：规则状态、待执行意图、可训练知识和审计日志具有不同的更新、失效及恢复语义。其次，跨实例 KV 复用的收益不仅取决于命中率，也取决于索引一致性和租约有效性；错误命中可能比未命中更危险。最后，自动生成推理 Kernel 的评估应分开讨论功能正确性、内存安全和真实硬件性能。以上是基于公开论文及 PR 的系统研究判断，不是已有框架完成验证的事实。

## 今夜白的观察

本周材料显示，Agent 系统的研究重心正在由单次上下文拼接向持续状态转换扩展。但显式状态不是免费午餐：写入时解析可能出错，参数记忆可能难以撤销，前瞻性任务可能错误触发。真正值得持续追踪的是如何定义统一的版本、证据、失效和恢复边界。推理基础设施侧，KV 位置索引和租约的工程讨论提醒我们：分层缓存的正确性协议与数据传输性能同样需要进入系统评估。

## 重点进展

本期五篇论文分别揭示了 GPU 代码生成的可信性边界、长事件历史中的显式状态优势、未来意图的触发语义、参数与文本记忆的互补，以及自修改 Harness 的泛化验证。工程方面，外部 KV 索引和租约过期保护表明跨实例复用必须同时考虑查找效率和有效性协议。上述结论分别对应正文中的原始论文及 PR，不代表这些方案已在同一生产系统内联合部署。

## 深度分析

从状态生命周期观察，事件日志是可追溯输入，显式状态是增量计算结果，待执行意图是带触发条件的未来任务，权重记忆则是经训练固化的知识表示。四者具有不同的写入、查询、回滚和一致性成本。尤其在 Agent 长期运行时，仅衡量 token 节省量无法覆盖错误状态传播与意图误触发风险。与之类似，KV 的跨实例索引需要把命中预测与租约有效性分离评估；否则命中率提升可能掩盖失效读取。
