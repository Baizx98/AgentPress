# 今日概览

本期优先分析 2026 年 11 月 13 日首次公开、截至 11 月 18 日仍处于近七日窗口的六篇研究论文。它们围绕三条技术主线展开：多模态推测解码的接受率瓶颈、长程 Agent 的上下文保留与可复现评测、以及模型压缩与运行时审计。**这些论文并非 11 月 18 日首次发布**；本期将其作为近期尚值得深入讨论的一手材料，而非“今日新论文”。另追踪一项 vLLM P/D 工程提案，严格区分提案与已合并实现。

- **多模态推测解码需要视觉依赖感知**：MMFlash 发现不同视觉依赖程度的 token，其草稿接受率差异明显。
- **Agent 上下文管理开始直接优化保留决策**：CarryOn 把执行状态与可溯源证据分开，并以无需额外 LLM 调用的选择器控制上下文。
- **评测正在逼近真实执行环境**：GDP.xlsx 和 WebArena-Pro 强调文件产物、真实应用、任务隔离与严格成功标准。
- **模型状态并非无关历史的静态属性**：Contagious Fingerprints 表明，对话历史可能污染模型身份审计。
- **模型压缩可以从原始权重结构出发**：Concertina 通过折叠相邻层与低秩校正构造更小的模型。

# 核心论文与技术报告

## 1. MMFlash：多模态推测解码中的视觉依赖瓶颈

**来源与时效**：Sicheng Feng 等，2026-11-13 首次提交，[arXiv:2611.18482](https://arxiv.org/abs/2611.18482)，目前为作者标注的进行中工作。

**问题**：推测解码通常使用较小的 drafter 生成候选 token，由目标模型并行验证。但文本任务上有效的草稿机制，未必能充分预测强视觉依赖 token。论文以有无视觉输入时下一 token 分布的 KL 散度刻画 token 级视觉依赖程度。

**机制**：MMFlash 在训练时提高视觉依赖强、且 drafter 预测较差的 token 的权重；对于长视频输入，还引入稀疏注意力以削减冗余计算。其改动针对的是草稿质量和草稿阶段计算成本，而不是改变目标模型的验证正确性。

**证据**：作者报告，视觉依赖最低四分位 token 的接受率约为 46%，最高四分位约为 22%；在其多模态基准上实现最高 3.58 倍无损解码加速，相对 EAGLE-3、DFlash 的最高改进分别为 195.4% 和 17.1%。这些都是论文特定模型、输入及基准条件下的结果，不能直接推广为所有视频服务的收益。

**研究价值与限制**：该工作提示，推测解码的最优草稿策略可能依赖输入模态与 token 的条件分布。需要进一步验证长视频下草稿稀疏注意力的索引开销、GPU 批处理下的收益和质量稳定性。论文页面尚未给出可确认的正式代码仓库发布状态。

## 2. CarryOn：学习长程 Agent 应当保留哪些上下文

**来源与时效**：[arXiv:2611.17808](https://arxiv.org/abs/2611.17808)，2026-11-13 首次公开。

**问题**：长程 Agent 的工具调用、观察结果和中间推理不断累积；简单截断容易丢失关键证据，完整保留又提高 token 成本与延迟。该问题与普通聊天的历史窗口不同：Agent 需要同时保存任务进度、操作结果及可追溯的依据。

**机制**：CarryOn 将紧凑执行状态与带来源关联的细粒度证据配对，使用学习型选择器和自适应保留策略决定上下文内容，不要求为每次筛选额外调用 LLM。这里的“保留”是上下文信息选择，而不是对模型内部 KV Cache 直接执行压缩。

**证据**：作者在 AppWorld、OfficeBench 和 Tau2 Telecom 上、使用三种执行模型评估，报告宏平均任务成功率为 75.7%，比其最强对比方法高 6.7 个百分点，并提出成本感知评价指标。结果说明在这些工作负载中选择性保留有价值，但仍需考察不同工具链、异常重试与跨会话记忆的迁移性。

**研究价值**：Agent serving 的缓存策略若只看 token 数量，可能无法反映“证据丢失导致任务失败”的代价。CarryOn 为上下文选择的效用评价提供了可检验的研究路径。

## 3. GDP.xlsx：以真实工作簿产物衡量 Agent 的执行可靠性

**来源与时效**：Suhaas Garre、Sushant Mehta、Edwin Chen，[arXiv:2611.17766](https://arxiv.org/abs/2611.17766)，2026-11-13 首次公开。

**问题**：传统问答分数难以反映 Agent 是否正确修改复杂文件。GDP.xlsx 收集 13 个领域的 70 项真实电子表格工作请求，包含约 218 万个已填充单元格和 791 条二元评判标准。评测 Agent 在容器中操作工作簿，并由能打开产物文件的评测代理逐条检查。

**证据**：作者报告，在 20 种模型配置中，最高严格 pass@1 为 38.3%，中位数为 19.3%。严格通过要求满足所有适用标准，而非仅完成大部分步骤。评测框架与三个公开任务已释放，另外 67 个任务保留以降低基准污染。

**限制与价值**：这不是直接的 LLM 推理吞吐基准，也不证明特定 Agent runtime 的系统效率。但它强调可恢复执行环境、文件状态正确性与最终产物校验的重要性，适合与工具调用轨迹、快照和重试成本联合分析。

## 4. WebArena-Pro：多模态 Web Agent 的可复现执行基准

**来源与时效**：[arXiv:2611.17955](https://arxiv.org/abs/2611.17955)，2026-11-13 首次公开。

**问题与机制**：WebArena-Pro 设计 300 项任务，覆盖六类领域的 20 个自托管 Web 应用，将音频和视频纳入一等观察对象与交互动作，并在隔离环境中运行任务，支持并行、可复现评估。

**证据**：作者报告，若干 coding-agent 配置的成功率达到 62.3%，而其比较的最佳通用 Agent 配置为 30.3%。这是不同 agent harness、模型与工具栈的整体系统结果，不能将差距单独归因于基础模型能力。

**研究价值与限制**：该基准为分析 sandbox 初始化、工具延迟、状态隔离、并行复现与多模态观察成本提供更真实的实验入口。其公开基准覆盖有限应用类型，尚不能代表所有生产 Web 自动化任务。

## 5. Concertina：从教师模型的权重直接构造小模型

**来源与时效**：Ziyang Zhang 等，[arXiv:2611.18113](https://arxiv.org/abs/2611.18113)，2026-11-13 首次公开；论文声明代码已公开。

**机制**：Concertina 不从头训练一个结构独立的学生，而是把教师模型每 N 个相邻层折叠为一个重复执行 N 次的共享块；每次循环引入从对应原始层初始化的低秩校正，并以 token 级门控组合。这一方法将权重共享与局部差异恢复结合。

**证据**：在 Qwen3-4B 上，作者用 220 亿 token 蒸馏得到 2.27B 参数模型，报告常识与数学推理约保留教师 90% 的表现，八项基准平均保留约 84%。这反映的是特定压缩比例与训练配方，不能直接等同于推理延迟或显存同比例下降。

**系统启发**：共享层可能降低权重容量与带宽压力，但循环执行仍保留多次计算；其真实吞吐取决于 kernel、KV 结构、批大小和权重复用路径。应分别测量权重访存、计算量与端到端服务效率。

## 6. Contagious Fingerprints：对话历史会污染模型身份审计

**来源与时效**：Zailong Tian，[arXiv:2611.18104](https://arxiv.org/abs/2611.18104)，2026-11-13 首次公开。

**问题**：通过生成文本的风格指纹判断 API 后端模型，通常默认指纹由当前模型决定。论文发现，当模型接续另一模型的对话时，会模仿历史风格，导致身份识别器错误归因。

**证据**：作者报告，在一组 Claude Sonnet 被 DeepSeek 接替的测试中，替代模型检测指标从 0.97 降到 0.72；同厂商降级到 Haiku 的测试从 0.87 降到 0.54。其 Lineup 方法在相同历史上采样声明模型的参考回答，再比较被审计回答的排序；作者报告假阳性率 0.056，四轮审计后检出 0.81 的替代会话。

**限制与价值**：结果依赖作者选定的模型对、审计轮数与统计设定，不能作为所有 API 服务商的欺诈率。其核心启发是：安全监测必须控制上下文历史这个混杂变量，不能把无历史参考分布直接用于有历史运行状态。

# 开源项目的重要新闻

## vLLM Super Prefill：在 P/D KV 传输期间继续生成的提案

2026-11-11，vLLM 社区提出 [Issue #67024](https://github.com/vllm-project/vllm/issues/67024)，讨论一种可选的 Super Prefill 流程。传统 P/D 分离在 prefill 生成首 token 后，往往需要等待 KV 传输和 decode 实例接管；提案利用 KV 追加写入的特征，让 prefill 实例在传输提示词 KV 时继续输出 token，decode 实例接管时再补算这段新增 token。

**执行路径影响**：这一设想将原本串行的“首 token—KV 传输—decode”部分重叠，目标是减少交接等待时间。其代价包括额外的 prefill 端生成、接管时的重算以及流式输出切换复杂性。**状态为公开 Issue/提案，不能视为已发布的默认功能或已经验证的性能提升**。本期不把其他未核验合并状态的 PR 标题当作工程新闻。

# 前沿概念和技术

## 视觉依赖感知的 Speculative Decoding

MMFlash 使用有无视觉条件时的预测分布差异，量化 token 对视觉输入的依赖。与仅按文本概率训练 drafter 不同，这使草稿优化目标更接近多模态验证失败的真实来源。它并不意味着视觉 token 必须单独存储 KV，而是说明生成概率的条件结构会影响推测解码收益。

## 执行状态、证据状态与模型内部状态的边界

CarryOn 管理的是 Agent 可见的上下文内容；GDP.xlsx 和 WebArena-Pro 检查外部任务与环境状态；Contagious Fingerprints 则研究历史文本对模型输出行为的影响。三者共同表明，“Agent 状态”不是单一对象：可编辑执行产物、可引用证据、会话历史和推理 KV 具有不同的一致性、恢复与验证要求。这里是跨论文的系统分析，并非任一论文提出的统一标准。

# 对大模型推理与存储优化的启发

**首先，优化指标需要与实际执行路径对齐。** MMFlash 的接受率差异提示推测解码不应只报告平均草稿长度；P/D 交接提案提示只统计 KV 传输字节数也不足以描述用户可见延迟。端到端 TTFT、TPOT、额外重算和硬件占用需要共同测量。

**其次，Agent 上下文选择与底层 KV 缓存管理不能混为一谈。** CarryOn 决定哪些语义证据进入未来上下文，而 KV Cache 负责保存既有 token 的计算结果。前者改变输入内容，后者改变执行资源；二者之间可能存在耦合，但本期材料没有证明一个通用的联合优化方案。

**再次，评测需要包含状态正确性和恢复成本。** GDP.xlsx 对最终文件施加严格标准，WebArena-Pro 提供隔离执行环境。这些设计说明，仅报告 tokens/s 或单轮成功率，可能遗漏长程工作流中的状态污染、错误累积和重试成本。

# 今夜白的观察

本期最值得跟踪的变化，不是某一个单点加速数字，而是研究对象逐步从“单次生成”扩展为“包含上下文、工具、产物和状态迁移的完整执行过程”。MMFlash 展示输入条件对推测解码的影响，CarryOn 展示保留策略对长程成功率的影响，两个 Agent 基准把任务环境纳入评价，而模型指纹研究提醒我们：历史上下文本身会改变审计统计分布。

接下来值得持续检验三个问题：多模态草稿加速在高并发 serving 中是否仍成立；上下文压缩对跨会话任务成功率和缓存复用率有什么共同影响；以及在 P/D 切换、Agent 重试与模型替换时，怎样定义可验证的状态边界。这些是基于公开论文提出的后续研究问题，并非已有定论。

# 重点进展

本期的主要进展可以归纳为三组：MMFlash 通过视觉依赖度改善多模态草稿预测；CarryOn、GDP.xlsx 和 WebArena-Pro 分别从上下文筛选、最终文件产物和可复现环境推动 Agent 研究；Concertina 与 Contagious Fingerprints 则分别揭示权重共享压缩和会话历史审计的新问题。详细机制、数字及限制已在上文六篇论文的独立小节展开。

# 深度分析

**共同的系统边界是条件依赖性。** MMFlash 的草稿接受率依赖视觉条件，CarryOn 的保留决策依赖当前任务证据，模型指纹检测依赖历史上下文，WebArena-Pro 的成功率依赖 agent harness 与隔离执行环境。这意味着任何脱离输入条件、工作流状态和运行环境的单一平均指标，都可能误导系统设计。进一步实验应同时固定模型、硬件、工作负载与状态恢复语义，报告端到端成本和失败模式。
