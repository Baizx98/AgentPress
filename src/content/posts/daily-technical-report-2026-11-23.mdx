# 今日概览

本期优先收录 2026 年 11 月 17—18 日首次公开的两篇推测解码研究，以及 11 月 17 日发布的 vLLM TPU 插件版本说明。近 24 小时内未核实到足以取代这些一手材料的同等质量新论文，因此不将较早论文冒充今日首发。

1. **推测解码正在从固定策略走向硬件和负载联合配置。** SpecSearch 指出，同一种 drafter 在低并发与高并发下可能由加速变为减速。
2. **Draft 模型宽度并非必须继承 Target 模型。** NarrowSpec 通过缩窄 draft residual stream，降低推测开销而基本保留接受长度。
3. **KV 分页与混合状态的优化仍然强烈依赖后端。** vLLM TPU 插件的 128-token 页面与 GDN 前缀缓存改进，提供了具体的系统级实例。

## 重点进展

本节以近期公开的论文和正式工程发布为依据，聚焦推测解码与混合状态缓存的执行机制。

### 核心论文与技术报告

### 1. SpecSearch：面向硬件与工作负载的推测解码配置搜索

**原始来源：** [SpecSearch: Towards Hardware-Aware Efficient Speculative Decoding](https://arxiv.org/abs/2611.22296)，Selin Yildirim、Ali Zeyrek、Deming Chen；arXiv v1 于 **2026-11-17** 提交。

**解决的问题。** 推测解码并非无条件提升吞吐。论文给出的 RTX 5090 案例中，DFlash 在低并发时达到自回归解码吞吐的 3.50 倍，但在短输出、高并发条件下仅为 0.76 倍。这个反例表明，固定的 draft 长度、精度和策略不能跨工作负载直接复用。

**核心机制。** SpecSearch 将解码策略、draft 长度与数值精度放入同一搜索空间。首先使用考虑显存和计算约束的解析成本模型排除不可行配置，再在多种 GPU 上收集校准数据；另外训练一个基于 Jev 的预测器，使用冻结的 Qwen3-4B、LoRA 和线性校正层，为未校准的目标 GPU 预测高吞吐配置。其贡献并非提出新的 verifier，而是将运行时策略选择转化为硬件感知的配置优化问题。

**实验与证据。** 作者在 RTX 5090、H100、L40、MI300X 上评估：完整校准版本相对 vLLM 自回归解码平均吞吐为 2.01 倍，相对 vLLM 推测解码为 1.36 倍；预测器版本相对推测解码为 1.30 倍，并保留完整校准搜索吞吐的 97.36%。以上均是论文作者报告的特定测试集合结果，不代表所有模型、batch 或输出分布的通用加速。

**限制与价值。** 预测器的跨硬件泛化取决于训练时覆盖的 GPU 与工作负载分布，部署时还需考虑策略切换成本、延迟分位数和显存波动。该研究提示推理服务框架不应只暴露静态 speculative decoding 开关，而应将并发度、输出长度、显存余量和 drafter 成本纳入配置选择。

### 2. NarrowSpec：Draft 的隐藏维度不必与目标模型一致

**原始来源：** [NarrowSpec: Draft Hidden Width Need Not Match the Target in Speculative Decoding](https://arxiv.org/abs/2611.23835)，Alagappan Valliappan、Ankit More、Dheevatsa Mudigere、Jatin Mitra；arXiv v1 于 **2026-11-18** 提交。

**解决的问题。** DFlash 和 EAGLE-3 等依赖目标模型隐藏状态的 drafter，通常沿用目标模型 hidden width。这使得较小的 draft 网络仍可能在投影、激活读写和中间计算中承担较高成本。NarrowSpec 检验这一结构约束是否真正必要。

**核心机制。** 作者将 drafter 整条 residual stream 缩至原宽度的一半或四分之一，并研究输出适配方式。对于复用目标词表投影的 DFlash，训练后的输出 adapter 可折叠到投影中，使相应 logits 在浮点舍入误差范围内保持一致。这是对 draft 路径的结构性压缩，并不是直接裁剪目标模型的注意力 KV。

**实验与证据。** 论文覆盖 DFlash 与 EAGLE-3 两类 drafter，目标模型为 Qwen3-8B（NVFP4）与 GPT-OSS-20B（MXFP4），在 SGLang、B200 和 DGX Spark GB10 上测试。batch=1、temperature=0 时，端到端解码加速在 B200 为 1.06—1.12 倍，在 GB10 为 1.13—1.44 倍；batch 从 32 增至设备可容纳上限时，最高为 1.21 倍。作者称所测试的窄 drafter 均未慢于完整宽度版本。

**限制与价值。** 这些数据来自限定模型、精度、硬件和解码配置，不能推导到所有采样温度或任意推测方法。其启示在于 draft 的激活宽度、投影带宽与目标模型 KV 的容量是不同的优化维度；应分别测量 proposal latency、acceptance length 和最终 tokens/s，避免只用接受率判断性能。

## 开源项目的重要新闻

### 3. vLLM TPU 插件 v0.33.0：KV 页面、GDN 前缀缓存与调度路径变化

**原始来源：** [vllm-torchtpu v0.33.0 官方 Release](https://github.com/vllm-project/vllm-torchtpu/releases/tag/v0.33.0)，**2026-11-17** 发布。该版本与 vLLM v0.33.0 对齐，发行说明汇总 134 个相关 PR；这里仅选取有明确推理路径影响的改动。

**KV 分页。** 对 max_model_len 大于 8192 的 dense FLASH_ATTN 模型，默认 KV page 从 16 token 改为 128 token。官方在 Qwen3-32B、TP=8、8k 输入/1k 输出、并发 64 的配置下报告总 tokens/s 提升 47.3%；在特定 Raiden KV offload/prefix reuse 基准上报告 3.6 倍。这是 TPU 后端的特定配置结果，不能直接作为 GPU PagedAttention 页面放大的通用收益。更大页面也可能提高内部碎片或改变短请求的资源效率，需要单独测试。

**混合状态缓存。** GDN 的内部 prefill checkpoint 允许 chunk 继续执行到 prompt 末尾，而不是被最后一个可缓存 block 提前截断。官方在 Qwen3.5-397B-A17B-FP8 的 PP/PCP 与 TP/PCP trace 上报告平均 TTFT 降低 11%—27%；同时修复了 MTP 下 block 边界的 GDN 状态正确性，并调整 compact-mamba 引擎的 scheduler block 计费。这说明混合注意力模型的缓存不能只考虑传统 attention KV，还需要准确维护递推状态与 checkpoint 边界。

**其他改动与限制。** 新版适配了 KV cache planning 模块迁移、draft KV 标识和 RayDistributedExecutorV2；单芯片 dense text 模型可使用 Multi-LoRA，官方明确其不支持 DP/TP/PP/CP 或 speculative decoding，并可能使无 adapter 请求也变慢。上述能力均以官方 Release 为准，属于已发布实现，而不是独立跨平台性能结论。

## 前沿概念和技术

**硬件感知推测解码。** SpecSearch 使推测解码从单一算法选择扩展为“算法 × draft 长度 × 精度 × GPU × 并发负载”的联合决策问题。其研究对象是可部署的吞吐最优配置，而不是单次 token 验证的理论接受率。

**窄残差流 drafter。** NarrowSpec 区分目标模型的隐藏宽度与 draft 模型自身的计算宽度。缩窄后是否真正加速，仍取决于模型层数、投影算子、显存带宽和验证过程的重叠程度。

**混合模型状态 checkpoint。** TPU Release 中 GDN 的 prefill checkpoint 提醒我们，线性/递推注意力状态与传统 KV 块并非同构。缓存复用的正确性依赖模型状态边界、执行阶段以及 MTP 等路径上的一致性，不能仅通过 token 前缀相同推断状态可安全复用。

## 深度分析

### 对大模型推理与存储优化的启发

第一，**性能最优策略具有负载条件性**。SpecSearch 的高并发反例说明，离线单请求 benchmark 的最佳 drafter 不一定适合在线 serving；吞吐、TTFT、TPOT、尾延迟和显存预算应共同进入评估。

第二，**应区分 draft 计算资源与 target 状态资源**。NarrowSpec 降低的是 proposal 端计算和激活相关开销；这与 KV 卸载、分页和跨请求缓存是不同路径。系统评估时应分别测量 draft、verify、KV 访存、调度和同步成本，才能定位端到端收益来源。

第三，**缓存粒度必须服从模型状态语义**。vLLM TPU 的 128-token 页面实验表明更大页面可能减少部分管理开销，但 GDN checkpoint 修复也表明状态边界正确性不能让位于吞吐优化。对 hybrid attention、Mamba/GDN 等模型，应显式测试分块、前缀命中、MTP 与跨请求复用的组合情况。

## 今夜白的观察

这批材料形成一条明确主线：推理加速正从“单个算法更快”转向“运行时能否在正确的负载、硬件和模型状态约束下选择正确的执行路径”。SpecSearch 强调选择机制，NarrowSpec 缩小 draft 的实际执行代价，TPU 插件则展示 KV 页面和递推状态边界如何影响部署性能。三者均提示，系统论文中的性能结论必须绑定清楚的硬件、并发、序列长度与模型架构。

值得继续跟踪的公开问题包括：策略预测器在负载突变时的切换开销；窄 drafter 在高温采样和更复杂验证树上的接受率；大页面在碎片严重的混合长度请求下的收益边界；以及混合注意力状态在前缀缓存、MTP 和卸载路径之间的一致性。上述均为基于公开材料提出的研究问题，并非已证实的结论。
