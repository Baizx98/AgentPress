## 今日概览

截至北京时间 2026 年 11 月 11 日，近一周值得关注的主线是：**KV 卸载从容量扩展转向受 TPOT 约束的全流程优化；Agent 的状态接口与最小权限正在成为基础设施的一部分。** 本期精选三篇 11 月 5—6 日公开的论文及一项 11 月 10 日新建的工程 PR。论文结果均为作者报告，不等同于跨平台通用收益。

- FlashOffloading 同时优化 prefill 和 decode 的 KV 卸载，而不是仅以更大可服务上下文作为目标。
- Agent Skills 不只是提示词或工作流描述，也可作为子 Agent 资源授权的训练信号。
- Lea 将运行、会话、事件和可持久化的证明蓝图暴露为应用无关接口，支持跨前端接续。
- vLLM 新增 GDS 文件系统 KV 卸载的草案 PR，尚未合并，不能视为已发布能力。

## 重点进展

本节集中分析三项近期一手研究：在线 KV 卸载的 SLO 约束、子 Agent 授权训练和可接续的正式化 Agent 运行时。

## 核心论文与技术报告

### 1. FlashOffloading：面向在线 SLO 的全流程 KV 卸载

**来源与时间：** Xuan Wang 等，2026-11-05 首次公开，[论文](https://arxiv.org/abs/2611.07542)。**新增点：** 本期首次纳入该近期工作。

**问题。** 将 KV 从 HBM 移至 DRAM 可以提高并发容量，但 host-to-device 数据传输、索引与缓存管理可能使 TPOT 恶化，导致容量收益无法兑现为符合服务等级目标的吞吐。

**机制。** 作者提出以主机 DRAM 为中心的方案，在 prefill 与 decode 均卸载 KV；prefill 使用滚动 HBM 缓存，decode 使用热数据缓存，并设计反向稀疏索引和计算—加载重叠内核。其关键不是单纯压缩传输量，而是协同优化缓存驻留、检索与算子执行路径。

**证据。** 在 Ascend 910C、PD 分离、GLM-5.2 与 MTP3 推测解码的作者实验中，在 30 ms TPOT 约束下，prefill 吞吐最高提高 1.38 倍、decode 吞吐最高提高 1.91 倍。论文称实现已集成至 [vLLM-Ascend 的 releases/v0.30.0 分支](https://github.com/vllm-project/vllm-ascend/tree/releases/v0.30.0)。

**限制与价值。** 上述峰值提升依赖特定硬件、模型、推测解码及 SLO；不能直接外推至 CUDA GPU 或其他负载。其系统意义在于评价 KV 卸载应同时报告容量、端到端吞吐与 TPOT 合规性，而不能仅比较 KV 命中率。

### 2. From Procedures to Permissions：从 Agent Skills 学习子 Agent 最小权限

**来源与时间：** Wenkai Yu、Ning Ding、Wentao Zhang、Yehui Tang，2026-11-06，[论文](https://arxiv.org/abs/2611.08905)。**新增点：** 将技能描述中的操作步骤转化为授权监督信号。

**问题。** 子 Agent 即使完成任务，也可能获得超出所需的工具和工作区权限。成功轨迹只能证明“访问过什么”，无法证明“必须访问什么”。

**机制。** 方法从 Agent Skills 中合成任务与逐步程序，在交互环境中执行子任务委派，验证执行轨迹，再构建同时监督任务执行与授权决策的 SFT 数据。由此将权限决策从静态的全局允许列表，转向依赖当前子任务的工具及文件范围。

**证据。** 作者报告，在 ClawArena-Team 上使用 Qwen3.5-35B-A3B，工具权限精确率提高 13.4 个百分点、工作区权限精确率提高 24.1 个百分点，整体任务成功率提高 11.6 个百分点；并在 Terminal-Bench 2.1 和 SkillsBench 上进行任务能力评估。

**限制与价值。** 训练数据中的步骤与验证环境仍可能遗漏真实生产系统的隐含依赖；权限精确率也不直接等价于抵御恶意攻击的能力。这项研究提示 Agent runtime 应把资源授权与任务分解、执行轨迹及状态恢复共同设计。

### 3. Lea：支持人类持续干预与跨客户端接续的 Agent Backbone

**来源与时间：** Shaswat Patel 等，2026-11-06，[论文](https://arxiv.org/abs/2611.08849)。**新增点：** 将正式化证明中的 Agent 执行从单一客户端抽象为共享的 run、session 与 typed event API。

**问题。** 自动证明系统偏向一次性自主运行，通用 coding harness 又要求研究者自行拼装 Lean 工具。用户在运行中介入、保留证明计划、切换界面并延续状态并不容易。

**机制。** Lea 内置蓝图、Lean LSP、Loogle 和 SafeVerify，公开统一的运行、会话和类型化事件接口。LeaChat 与 LeaOverleaf 共享后端状态；论文描述了根据文档改动使受影响的形式化结果失效的机制。

**证据。** 作者给出 Durfee square 生成函数的案例，展示研究者以自然语言引导证明分解、系统生成 Lean 开发并接受局部修正。论文称 Lea 及两个应用已开源，但该案例不能替代大规模跨任务统计评估。

**限制与价值。** Lea 的领域特定 Lean 工具链不意味着可直接移植到通用软件工程 Agent。不过，运行态、持久蓝图、事件流与客户端解耦的架构值得作为 Agent 基础设施的设计参照。

## 开源项目的重要新闻

### vLLM：GDS 文件系统 KV 卸载进入草案评审

**新增时间与状态：** 2026-11-10，vLLM [PR #66805](https://github.com/vllm-project/vllm/pull/66805)，**Draft，尚未合并**。该 PR 自述是 [RFC #54777](https://github.com/vllm-project/vllm/pull/54777) 的第二部分，在文件系统 KV offload 基础上增加 GPU Direct Storage（GDS）路径。

提交描述包含基于 cuFile 的文件系统卸载 worker、GDS manager、spec 与绑定层，并适配既有 IOCompletion、FileOp、ThreadPoolFSWorker 和分块管理 API。其预期执行路径是通过 GDS 连接 GPU 与 NVMe，减少传统主机内存中转需求；但当前 PR 未提供足以验证端到端吞吐提升的正式基准，因此**不能宣称 GDS 已带来特定性能增益**。硬件、驱动、文件系统和 cuFile 兼容性也需要在合并前验证。

## 前沿概念和技术

**SLO-aware KV offloading。** FlashOffloading 强调卸载策略不应只追求最大缓存容量，而应以 TPOT 约束下的可交付吞吐为优化目标。此处 SLO-aware 是对论文目标的概括，不是声称其发明了统一行业术语。

**Task-conditioned authorization。** “从程序到权限”的核心是将每次子任务的资源需求显式化；它与普通的工具调用成功率不同，也不能被简单归入提示词安全。

**Application-neutral Agent state API。** Lea 将 run、session、typed event 和持久蓝图分离于前端，使人类干预、跨客户端接续及局部失效成为可实现的系统行为，而非聊天历史的附属功能。

## 深度分析

从上述论文和工程草案出发，下面分别讨论缓存性能指标、数据移动接口和 Agent 状态边界的系统含义。

## 对大模型推理与存储优化的启发

第一，**容量和性能必须联合评价**。分层 KV 管理至少需要同时观察 HBM 占用、主机或 SSD 数据传输、TTFT、TPOT、并发和 SLO 达标吞吐。FlashOffloading 的结果表明，单独扩容不能保证在线收益。

第二，**数据移动接口正在变成推理框架的核心扩展点**。vLLM 的 GDS 草案尝试复用现有文件系统与分块卸载抽象，说明设计稳定的 I/O completion、worker 与数据块接口可能比为单一设备写专用路径更利于演进；这一判断仍需后续合并及性能验证。

第三，**Agent 的状态与权限应有独立语义**。Lea 的 session/event/blueprint 与 Skills 授权研究分别揭示了状态持久化、跨端恢复及最小权限的问题；在通用 Agent runtime 中，缓存可复用不代表状态可安全共享，工具执行成功也不代表权限配置合理。

## 今夜白的观察

这几项材料共同指向一个系统设计转变：优化对象正从单个算子或缓存命中率，延伸到**受约束的完整执行过程**。推理服务需要考虑 SLO 下的数据供给路径；Agent 系统需要考虑任务进展、可恢复状态和资源授权。值得持续跟踪的是：GDS 卸载在真实混合负载中的端到端成本、权限训练信号的跨环境泛化，以及持久 Agent 状态接口如何与底层缓存生命周期协调。这些是从公开材料提出的研究问题，而非已被证明的结论。
