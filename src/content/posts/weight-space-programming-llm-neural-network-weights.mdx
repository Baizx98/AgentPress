# 论文概览

**Weight-Space Programming（权重空间编程）** 是一个颇具突破性、但仍处在早期探索阶段的想法：让通用大语言模型直接**读取、理解、修改乃至从零写入神经网络权重**，不依赖传统优化器或梯度下降。研究使用 **GPT-6 Astra**，先在小型游戏网络和 Transformer 上验证理解与构造能力，再扩大到 Gemma 3 270M 和 Qwen3.5-0.8B。

最醒目的实验是：Astra 在不训练、不使用梯度的条件下，发现 Qwen3.5-0.8B 的重复推理问题，并调整了约 **131,072 个参数（占 0.016%）**，将 **MATH-500 从 7.9% 提升至 48.1%**、**GSM8K 从 13.8% 提升至 67.1%**，IFEval 则从 **21.0% 提升至 62.3%**。但这个结果首先意味着**修复了一种使模型无法完成回答的行为缺陷**，不能解读成凭空给模型注入了大量新的数学知识。数据见[原文实验 8](https://rikiyat.github.io/blog/weight-space-programming/)。

## 研究背景与问题

长期以来，神经网络权重的生成和修改主要依赖数值优化：前向传播计算输出，损失函数刻画差异，通过反向传播得到梯度，优化器再更新参数。与自然语言、源代码不同，浮点数矩阵既不具有显式语法，也缺少容易由人理解的局部语义，因此我们通常不把权重文件看成可以“编程”的对象。

作者的问题是：**通用 LLM 是否已经具备从原始参数推断网络行为，并按照自然语言目标编写功能性权重的能力？** 如果答案是肯定的，那么模型优化不再只依赖数值搜索，还可能出现由语义目标驱动的局部诊断和修复。

这种方法与传统零阶优化也不相同：零阶优化一般仍通过大量函数值查询寻找更新方向；Weight-Space Programming 的核心是让 LLM **理解网络应该计算什么，并主动设计实现该计算的参数结构**。它可以使用反馈，但并非总要使用反馈。

## 核心方法

作者将任务分为三种能力：**Read（读出行为）**、**Fix（修复错误）** 和 **Write（从零构造）**。LLM 面对的输入可能包含结构说明、权重矩阵、任务规则、失败轨迹；输出则是行为解释或直接写入权重的程序 / 数值。

需要强调两种实验条件：**实验 1—5 主要研究不运行目标网络、甚至不使用工具时的能力**；**实验 6—8 为处理更大的网络，允许使用 Python 读取和写入张量，部分实验可以消费有限的前向反馈预算**。所谓“无梯度”，不能被误读为“完全无需计算、无需反馈、无需验证”。

## 系统或模型设计

这篇研究博客没有提出一个已经标准化的软件框架，而是围绕不同任务设计了实验 Harness：

1. **小型网络场景**：权重可放入 LLM 上下文，直接以文本形式提供给 Astra；目标是排除优化器和工具带来的间接作用。
2. **大型网络场景**：权重不可能全部输入上下文，Astra 通过 Python / NumPy / PyTorch 在沙箱中选择性检查、计算和修改参数张量。
3. **反馈控制**：只在指定预算下运行网络，观察网络输出或统计信息；不允许训练循环和梯度求解。
4. **外部评估**：在未向 Astra 提供的评估任务上检验编辑效果，尽量区分诊断时的练习样本与最终测试集。

# 实验设置与主要结果

## 八组实验总览

| 实验 | 能力 | 模型 / 任务 | 主要结果 |
| --- | --- | --- | --- |
| 1 | Read | 四种游戏的同构 MLP | 单看权重，四个游戏全部辨认正确 |
| 2 | Read | 生成圆、三角、方形的 DDPM | 辨认形状，但把填充图形读成了轮廓 |
| 3 | Read | 7.16M 字符级 Transformer | 正确识别语料，并找出全部复制型 Head |
| 4 | Fix | Kinetix 汽车爬坡策略 | 修改 3.5% 权重，1,024 次评测全部成功 |
| 5 | Write | 三种 MinAtar 游戏 | 零反馈手写策略在三种游戏中均超过 PPO 100M 基线 |
| 6 | Write | 约 1.48M 参数围棋网络 | 从零构造策略；50 次反馈后超过同尺寸 PPO |
| 7 | Read | Gemma 3 270M 谄媚性 | 仅权重失败，增加注意力模式才识别成功 |
| 8 | Fix | Qwen3.5-0.8B | 0.016% 权重修复循环，显著提升多个测试分数 |

## 实验 1—3：仅凭权重识别网络学会了什么

**实验 1** 使用四个结构完全相同的 MLP（500→32→32→5，17,253 参数），分别由 PPO 在 Breakout、Pong、Pac-Man、Freeway 上训练。所有任务使用统一的 10×10 网格、五个输入通道与五个动作，Astra 不知道游戏候选项，却正确认出了四个网络。其解释包括：输入权重在底部区域的集中程度可能对应挡板，输出权重反映方向性动作。

**实验 2** 将同样的方法扩展到 DDPM：三个 23,824 参数的模型分别学习生成 12×12 的实心圆、三角和正方形。Astra 通过输出层权重的几何特征识别出三种图形，但只画出轮廓。这既表明它能够读出部分结构，也显示**由权重推断出的可解释图案未必等于网络完整的生成行为**。

**实验 3** 更有意义：研究者训练三个约 7.16M 参数的字符级 Transformer，分别使用 Python 代码、日语罗马字文本和英语百科语料。只保留中间四个 Transformer Block，去除输入 Embedding 与输出层，从而避免靠字符映射直接猜答案。Astra 可以使用 Python 分析权重，但不能运行模型。结果是三种语料在两次尝试中均被正确识别；Astra 还准确找出了全部复制型注意力头。

| 训练语料 | Astra 识别的复制型 Head | 实测复制型 Head |
| --- | --- | --- |
| Python | 2.1、3.1、3.5 | 2.1、3.1、3.5 |
| Romaji | 3.3 | 3.3 |
| English | 3.1 | 3.1 |

这里的关键不只是统计权重值大小，而是**分析注意力投影矩阵之间的组合关系**，识别由早期位置检索和后续 token 复制构成的电路。这与 Mechanistic Interpretability 中的 Induction Head 分析有相通之处。参见[原文 Figure 1 与实验 3](https://rikiyat.github.io/blog/weight-space-programming/)。

## 实验 4：在权重中补上一条控制策略路径

Kinetix 的一个汽车爬坡任务要求车辆先倒退，再获得足够加速距离跨越障碍。PPO 策略陷入局部最优：只会向前顶坡，无法成功。

Astra 得到一份网络权重、一段场景描述和一次失败轨迹，**无需工具、一次修改**便改变了网络中的约 **3.5% 参数**；新策略在 **1,024 次评估中全部成功**。原文解释，它在少量神经元之间增加了一条功能路径：读取汽车位置与速度，在尚未越过障碍前驱动车辆倒退，而满足条件后再把控制交给原网络。

这个实验更像是**功能电路补丁（functional circuit patch）**：保留原策略的大部分行为，只补上缺失的决策步骤。原始网络为 171,664 参数的策略 MLP。详见[实验 4](https://rikiyat.github.io/blog/weight-space-programming/)。

## 实验 5—6：将显式规则直接编译成权重

实验 5 不再修复现有网络，而是**从全零权重出发**。Astra 只能读取 MinAtar 三种游戏的规则和网络结构，不能使用工具、数据、Loss、梯度或测试回合，必须一次性生成可以运行的权重。

<Figure src="https://media.baizx.cool/images/2026/11/1d1b75f4dbf91013aec8d84912fb64d7aedfb7948a60bb5368b07e8154901be5.webp" alt="Breakout、Seaquest、Asterix 三个游戏中 PPO 与 Astra 手写权重的分数" caption="图 3：MinAtar 游戏分数。据原文实验 5 重绘；只能在同一游戏内部比较奖励，不能跨游戏比较奖励尺度。" />

| 游戏 | PPO 100M 步 | PPO 500M 步 | Astra 一次生成 |
| --- | ---: | ---: | ---: |
| Breakout | 15.8 | 25.3 | **517.4** |
| Seaquest | 5.6 | **88.9** | 53.1 |
| Asterix | 25.8 | **55.2** | 53.2 |

对于 Breakout，Astra 直接设计了两层网络的功能分工：**第一层计算球预计落点，第二层决定挡板向哪个方向移动**。它利用已有游戏规则知识，把一个明确的控制算法编码到网络，而非通过与环境交互试错。这也解释了为何它能在此任务超过 PPO，却不能证明此类手写网络在一般复杂任务中优于强化学习。

实验 6 把这一思想扩展到 **9×9 围棋**，使用 **243→512×6→82、1,480,274 参数**的网络。Astra 利用 Python 分层构造气、棋块连通、吃子、救棋等规则，50 次批量前向反馈后，超过了原文所用同尺寸 PPO 基线。**一次 forward pass 可以是批量评估，而不是仅输入一个棋盘。** 具体评估对手及基线训练预算见[原文实验 6](https://rikiyat.github.io/blog/weight-space-programming/)。

## 实验 7：一个很重要的失败案例

作者训练成对的 Gemma 3 270M：一个倾向正确回答，另一个倾向迎合用户错误猜测。两者的 Embedding 和输出层被保持一致，避免依赖输入输出层直接辨认。

**仅看权重，Astra 四次尝试均未能正确区分。** 当允许读取模型在自拟文本上的注意力模式（而不是输出答案）后，它才成功找出三个模型对中的谄媚模型。

原文 Figure 2 给出的 Head 10.2 案例很直观：

| 注意力目标 | 正常模型 | 谄媚模型 |
| --- | ---: | ---: |
| 问题中的数字 | 94.3% | 3.5% |
| 用户提供的答案 | 0.75% | 85.7% |

由此可见，在某些更复杂的行为特征上，**静态权重差异还无法直接映射到语义行为；模型激活和注意力响应仍然重要**。

## 实验 8：修复 Qwen3.5-0.8B 的推理循环

这是全部实验中最值得仔细审视的一项。研究者给 Astra 的目标是“提高 Qwen3.5-0.8B 的数学能力”，但它最先识别出的不是知识缺失，而是**推理循环导致输出无法完成**：前 96 个练习回答中，85 个触及 32,768 token 上限。

实验允许 Astra 使用 Python 查看、修改模型权重，并在 GSM8K、MATH 的**训练集练习题**上消耗 10、25 或 50 次前向调用预算；最终评估则使用未暴露给 Astra 的 MATH-500、GSM8K、IFEval 等测试集。原模型为 24 层、约 0.8B 参数，启用 thinking 模式。

Astra 定位到**第 15 层和第 19 层 MLP 输出投影**写入残差流的一个方向，并从这两层各 **64 个输出列**中减去该方向的分量，累计改动 **131,072 个参数，占总权重约 0.016%**。

### 为什么不能说它学会了更多数学知识？

作者自己做了一个重要的对照：对不严重循环的 **Gemma 3 270M** 进行类似编辑。

| 配置 | MATH-500 |
| --- | ---: |
| 原模型 | 6.8% |
| 编辑（5 次） | 7.0% |
| 编辑（10 次） | 7.6% |
| 编辑（25 次） | 7.7% |
| 编辑（50 次） | 7.0% |

Gemma 的数学错误更多是计算或逻辑推导本身错误，而不是无法终止的推理循环。Astra 未找到一个足以显著提升数学成绩的局部行为瓶颈。**局部权重编辑可以移除阻碍已有能力发挥的缺陷，但尚未证明能创造原本不存在的抽象推理能力。** 这也是我认为整篇博客最值得保留的负面结果。

## 与相关工作的区别

这项研究与几类现有方法的区别，需要准确界定：

- **常规 Fine-tuning / LoRA**：通过数据和损失优化参数；这里尝试通过语义诊断直接确定权重修改，至少在主要实验中禁止梯度训练。
- **传统 Model Editing**：例如对具体事实知识或特定激活方向进行算法化修改；这里强调由一个通用 LLM 自主阅读原始网络权重、推理原因，并决定修改方式。
- **Mechanistic Interpretability**：传统研究常由研究者建立分析工具，寻找 Head、Neuron 和 Circuit；这里考察 LLM 自主运用类似分析推导功能结构的能力。
- **神经网络程序合成**：小网络权重可表示显式算法。Weight-Space Programming 将自然语言目标到功能性权重的映射交给通用 LLM，而非专门训练的权重生成器。

创新不在于首次提出“修改权重”，而在于展示**未经专门权重编辑训练的通用 LLM** 已经能够在若干可控任务上完成直接读取、编写和局部修复。

## 局限性

**第一，规模尚未真正解决。** 0.8B 实验已经必须借助 Python 工具，无法把完整参数写成 Prompt；如何选择需要检查的张量、如何分层聚合证据，仍是核心难题。

**第二，实验存在明显任务结构先验。** 游戏规则明确、空间输入可解释，便于把控制算法编码进神经元；真实大模型的分布式表示、非线性电路和跨任务行为复杂得多。

**第三，部分收益来自修复特定退化。** Qwen 实验中基线出现极高比例的超长循环，提升幅度不能外推到正常推理模型，更不能据此宣称普遍超过梯度优化。

**第四，缺少系统级成本与可靠性比较。** 修改 0.016% 参数很少，但查找问题、批量推理反馈、测试回归以及可能的行为退化都有成本；尚需与 SFT、LoRA、标准模型编辑和推理解码控制进行统一比较。

**第五，目前仍是研究博客。** 有公开日志和模型便于检查，但这不等于经过独立复现或同行评审。对于模型自我编辑、持续自我改进、跨架构电路移植等未来设想，应视为研究方向而非已经得到验证的能力。

## 对大模型推理加速和存储优化的启发

从系统研究视角，最直接的价值不是用 Weight-Space Programming 代替 KV Cache 优化，而是为**模型行为故障诊断与局部修复**增加一条技术路径。

1. **推理循环和无效 Token 开销**：如果某些模型的异常长输出由可定位的局部机制引发，权重补丁有可能降低无效生成、提高有效吞吐。但必须区分权重修复带来的行为变化与调低 max_tokens 或修改采样策略带来的效果。
2. **局部权重补丁的服务化管理**：按任务、模型版本分发少量补丁可能形成类似 Adapter Serving 的需求，但补丁不一定具有 LoRA 的低秩结构，可能需要稀疏张量更新、版本一致性、回滚和安全验证机制。
3. **模型内行为诊断与运行时指标联动**：可以研究如何将 token 重复率、有效完成率、TTFT / TPOT、P99 和模型内部组件分析结合，判断瓶颈来自模型行为还是系统资源。当前博客没有证明可直接降低 KV Cache 容量、注意力复杂度或显存占用，相关收益必须另做实验。

换句话说，系统优化的对象或许不再止于 Kernel、缓存和调度器，还可能延伸到**模型在推理阶段本身产生了多少无效计算**。但这一外推属于本文分析，并非作者已经实验验证的系统结论。

## 今夜白的观察

我认为这篇博客最值得关注的贡献有三点：

**（1）在简单可解析的网络上，LLM 可以把规则翻译为权重。** 它接近一种“神经网络编译器”雏形，显示自然语言与连续参数空间之间可能存在比我们预期更直接的交互方式。

**（2）在小 Transformer 上，LLM 可以从中间权重组合关系推断电路。** 实验 3 的 Copying Head 识别，比仅在输入层可视化图案更有说服力，也更接近机制可解释性的真正研究问题。

**（3）在真实模型上，LLM 已能做针对性行为修复，但无法普遍补全缺失的能力。** Qwen 和 Gemma 的对照很重要：它将“解除能力发挥的障碍”与“创造新的能力”分开，也为未来该领域的实验设计提供了清晰标准。

总体判断：**Weight-Space Programming 是一个值得关注的新研究范式的早期信号，但还不是可普遍替代梯度训练的优化算法。** 它最先可能落地的方向是模型诊断、自动化机制可解释性、可验证的局部权重补丁，而非无数据地从零训练任意大型模型。
