# 今日概览

本期以 **Agent 记忆的有效性、可追溯性与训练接口** 为主线。近 24 小时可核验的高价值系统论文有限，因此重点分析 11 月 17 日公开的新论文，并补充近七日内具有直接技术价值的研究；工程侧只保留有明确代码路径和状态说明的 PR。具体观察有三点：第一，简单的检索式记忆在既有基准上可能不逊于复杂记忆架构，但“检索到”不等于“能够正确行动”；第二，持久文件工作区正成为长程 Agent 训练中可操作的记忆接口；第三，记忆来源追溯与原始轨迹复核是避免错误经验污染后续决策的重要机制。

## 重点进展

本节围绕近七日内可核验的 Agent 记忆论文展开，重点比较其问题定义、系统接口与评测证据。

### 核心论文与技术报告

### 1. RAG in a Trenchcoat：检索分数不能替代记忆驱动的行动能力

**新增点与来源。** Jingyu Liu 等于 **2026-11-17** 首次公开 [RAG in a Trenchcoat](https://arxiv.org/abs/2611.22179)，arXiv 页面注明 NeurIPS 2026 Main Conference。该研究不是简单提出又一种复杂记忆图，而是反问：复杂记忆操作究竟在何种任务中产生了超出检索的收益？

**核心机制。** 作者构建刻意简化的 BRIDGE：链式 observation notes、BM25 与余弦相似度混合检索、按时间顺序呈现记忆。它不依赖复杂的反思、图合成与多级事实更新流水线。研究进一步设计五类对抗性测试，要求 Agent 应用问题中未直接提及的已记忆规则或模式，区分“召回正确事实”与“利用事实采取正确行动”。

**实验与证据。** 根据作者摘要，在 LongMemEval-S 与 BEAM 上，BRIDGE 与既有最优方法在 bootstrap 置信区间内相当；在 EverMemBench 上，同一 reader 条件下领先最强记忆基线 **5.7–6.3 个百分点**。单次查询 reader prompt 约 **5–7K tokens**，每次写入或查询使用一次 LLM 调用。五类探针各含 20 个场景；原子事实抽取型记忆在规则应用上更强，块摘要型记忆在模式归纳上更强。

**限制与意义。** 这些结论属于作者在指定基准、reader 与 grader 上的结果，不能推导出复杂记忆系统普遍无用。更关键的是：记忆系统的评价应加入“规则执行、模式迁移、冲突处理”的行为指标，并报告 reader、检索上下文预算和 token 成本。论文未在 arXiv 摘要中明确给出可用代码仓库，本文不将其标为已开源。

### 2. CAMP-II：让文件操作成为 Agent 记忆策略的一部分

**时间核验。** Lirui Luo 等的 [Coding Agent Memory Post-Training II](https://arxiv.org/abs/2611.14009) 于 **11 月 10 日**首次提交，**11 月 12 日**更新 v2；属于七日回溯边界上的补充论文，**并非 11 月 19 日新发布**。

**问题与方法。** 现有 Agent 记忆后训练常引入专门的 memory tool 或 compaction 协议，但教师模型未必熟悉这些接口，学生也难以采样足够多的有效记忆动作。作者构建 CAMG-II，覆盖 Shop、Coding、AutoResearch、General、Visual 五类长程环境，在原生任务接口之外提供 Bash 与跨 context replacement 保留的工作区。CAMP-II 使用完全异步的 on-policy distillation，让同一策略学习创建、修改、搜索和复用文件。

**实验与证据。** 作者报告在 CAMG-II 上取得最强 OPD 基线 **2.97 倍的增益**，并在 Terminal-Bench 2.1 与 SWE-Bench Pro V2 上观察到任务成功率改善。这里的“2.97 倍”指**相对基线的增益倍数**，不能误写成任务成功率或吞吐量达到 2.97 倍。论文提供[项目页面](https://liruiluo.github.io/)；具体代码可用性需以项目仓库实际文件为准，不能仅凭项目页存在推定全部训练资产开放。

**限制与意义。** 该研究依赖可持久化文件空间、Bash 接口及训练环境配置，尚不能直接证明所有工具协议都适合文件化。系统层面值得注意的是：记忆不再只是检索服务返回的文本，而是具备写入、版本演化和跨上下文存续语义的运行时对象。评测时应将文件操作成本、恢复成本与最终任务收益联合报告。

### 3. WikiTrace：记忆需要能回到原始执行证据

**时间核验。** Yukyeong Lee 等的 [Don't Just Trust Your Memory](https://arxiv.org/abs/2611.14320) 首次公开于 **11 月 10 日**，属于回溯补充。arXiv 明确标注该论文处于 ACL Rolling Review 审稿阶段，**不得视为已录用**。

**问题与机制。** Agent 往往把历史轨迹蒸馏成简短经验，但经验可能本身错误、被错误套用，或丢失关键条件。WikiTrace 将每条 insight 关联到成功/失败原因摘要及原始 trajectory。当 insight 缺少执行细节、彼此冲突或来自失败任务时，Agent 可以借助终端工具沿证据链回溯，修正判断后再行动。

**实验与证据。** 作者在五个 agentic benchmarks 上比较现有记忆方案及“只提供相同 insights”的基线，报告任务表现改善并减少 memory-induced degradation。作者在论文页面提供了[代码链接](https://arxiv.org/abs/2611.14320)；具体性能差值及配置应以论文表格和仓库为准，此处不补造统一百分比。

**限制与意义。** 证据回溯引入额外存储、索引与工具访问成本，且原始轨迹本身可能包含不可信工具输出。该工作提示记忆数据模型至少要区分**结论、形成过程、原始证据和适用条件**；仅凭语义相似度检索难以保证记忆可安全复用。

## 开源项目的重要新闻

### SGLang：gfx1250 paged prefill 的实验性内核移植

[SGLang PR #51379](https://github.com/sgl-project/sglang/pull/51379) 于 **2026-11-18** 创建，当前页面显示 **Draft**，并非已合并或已发布功能。它为 gfx1250 上的 uTLX 路径增加 paged prefill kernel，面向 BF16 query、GQA 8、head dim 64，支持 BF16 或 FP8 e4m3 KV、16/64 page size，以及全局或 2047/2048 key 窗口。实现按 tile gather page，并在共享内存中将 FP8 解量化到 BF16，复用原 BF16 计算路径。

**执行路径与边界。** 改动直接触及 attention prefill 的分页 KV 读取与精度转换，而非通用 KV cache 管理策略。PR 说明后续还需接入 Muse Spark 的不同 attention phase、DFLASH draft 和长上下文/滑窗 prefill；AITER shuffled 5-D cache 尚未移植。因此它更适合作为特定硬件与布局下的 kernel 工程观察，不能宣称已经在 SGLang 主线提供通用加速，也没有足够公开证据给出端到端加速倍数。

## 深度分析

三篇论文共同揭示记忆操作、记忆证据与实际行动之间的不同边界，以下从技术抽象和系统代价展开分析。

### 前沿概念和技术

**Memory-as-action 与 Memory-as-evidence 是不同的系统维度。** CAMP-II 讨论 Agent 如何学习执行持久化文件操作，强调写、读、修改的策略；WikiTrace 讨论记忆的可验证性，强调结论与证据的链接；BRIDGE 则说明即使检索足够准确，reader 是否真正应用规则仍是另一项能力。三者分别对应记忆的**操作接口、证据结构和行为评测**，不宜用单一的 retrieval accuracy 代表全部质量。

**记忆评测的因果边界。** BRIDGE 的对抗性探针揭示：在输入中出现相关事实，不等于后续动作受到该事实正确约束。这并不意味着论文证明了通用的“记忆因果性”理论；更准确地说，它提出了一组任务级行为测试，用以暴露常规召回指标难以识别的失败模式。

## 对大模型推理与存储优化的启发

从公开材料可以推导三个通用系统问题。其一，Agent 状态应同时支持**轻量索引与按需证据回溯**：高频检索只返回紧凑信息，出现冲突或失败信号时才访问完整轨迹，避免每次把所有历史塞进上下文。其二，持久工作区要求系统显式处理**跨上下文边界的文件状态、更新顺序和恢复一致性**，不能只用 Chat 的轮次缓存命中率评估。其三，性能评估必须把**检索 token、文件 I/O、工具等待、额外验证调用和任务成功率**放在同一成本账本中。以上属于基于论文机制的系统推断，并非作者已证明的通用部署收益。

在 GPU 侧，SGLang 的草案展示了另一个边界：即便 KV 已按 page 管理，真实内核仍需要处理 page gather、FP8 scale、共享内存 staging 与特定 head/layout 约束。KV 的逻辑管理抽象与物理执行效率应分别评估。

## 今夜白的观察

今日最值得持续跟踪的不是某种记忆结构取得新的单项 SOTA，而是**Agent 记忆研究正在分离三个过去容易混淆的问题：能否检索、能否正确使用、能否核查来源**。BRIDGE 说明复杂结构未必总能带来更好结果；CAMP-II 说明接口本身会影响记忆策略是否可训练；WikiTrace 说明“成功经验”并不天然可信。对系统研究而言，下一步值得关注具有真实工具间隔、跨会话恢复、文件变更和错误经验传播的 workload trace，以及统一计量任务收益和状态维护开销的基准。

本期没有把未核验的会议录用传闻、普通模型营销更新或缺少实现细节的 GitHub 标题列入正文；近期可核验材料集中于 Agent 记忆，因此不强行补齐全部研究方向。
