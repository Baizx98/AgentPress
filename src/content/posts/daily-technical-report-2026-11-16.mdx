## 今日概览

本期以北京时间 2026 年 11 月 16 日为截点，重点回看 11 月 9—12 日首次公开或更新、尚未在本站近期技术报告中发现专题介绍的四篇一手论文。没有把二手报道时间当作论文发表时间，也没有为了凑数加入无法核实日期的框架 Release。

1. **推理阶段可以跨模型拆分。** BridgeKV 将大模型 Prefill 与小模型 Decode 连接起来，核心不再只是 GPU 间迁移同一模型的 KV，而是学习不同模型之间的 KV 表示映射。
2. **Agent 的缓存命中率可能具有系统级正反馈。** 一项基于 vLLM、SGLang 的研究发现，短暂到达突发可能把长程 Agent 服务推入持续低命中、低吞吐状态。
3. **记忆质量不能只看召回。** WikiTrace 把压缩后的经验与原始轨迹关联，使 Agent 能够回溯证据、纠正错误经验。
4. **文件操作正在成为可训练的 Agent 记忆接口。** CAMP-II 使用持久工作区和 Bash 文件操作，通过异步 on-policy distillation 学习长程任务的记忆管理。

## 重点进展

本期重点进展集中在跨模型 KV 转换、Agent 服务稳定性以及可验证的外部记忆。以下四篇论文分别给出具体机制和作者实验数据。

## 核心论文与技术报告

### 1. BridgeKV：大模型 Prefill、小模型 Decode 的 KV 翻译

**来源与时间：** Payman Behnam 等，2026-11-09 首次提交，arXiv:2611.11761；[论文原文](https://arxiv.org/abs/2611.11761)。

**解决的问题。** 传统 PD 分离可以将计算密集的 Prefill 与带宽受限的 Decode 放到不同设备，但通常仍要求两阶段使用同一个模型。BridgeKV 更进一步：让大模型负责处理输入上下文，让更小的同家族模型生成输出，降低逐 Token Decode 成本。

**核心机制。** 作者训练一个轻量级 KV-stitching 模块，把大模型的 Prompt KV 翻译为小模型可消费的 KV。它通过局部层混合、分别针对 Key 和 Value 的非线性映射处理层数、形状和表示差异。两侧基础模型冻结，首先训练缓存对齐与下一 Token 预测一致性，必要时第二阶段再加入低秩适配器。与直接把 KV 字节复制到另一台机器不同，这里发生的是跨模型表示转换，必然存在额外计算及潜在质量损失。

**实验与证据。** 论文报告六组模型配对、五个数据集的 30 个设置中均优于可训练参数预算匹配的小模型微调基线；最多弥合相对于全程使用大模型的 80% 质量差距。单张 A40 上，Llama-3.1-8B 到 Llama-3.2-1B 的组合相对全程 8B 请求速度达到 3.0 倍。70B 到 1B 组合的最高 33.86 倍速度与 27.5 倍能耗改善来自包含到达、队列和缓存传输的**服务模拟**，不能写成真实集群测量。

**限制与意义。** 质量、模型家族兼容性、映射训练成本和输出任务分布决定了方案适用性。它提出值得系统界关注的新接口：跨模型 KV translation，而非仅跨实例 KV transfer。需要进一步考察多轮 Agent 中上下文不断增长时，映射误差是否累积，以及如何调度两种模型的容量与计算资源。

### 2. Bursts That Outlast Themselves：Agent Prefix Cache 的持续性退化

**来源与时间：** Wen Huang、Jack Liu，2026-11-10 首次提交；[论文原文](https://arxiv.org/abs/2611.13412)。

**解决的问题。** Agent 的多轮闭环请求会重复携带不断增长的历史上下文。Prefix Cache 命中时只需计算增量 Token，未命中时可能需要重新 Prefill 1 万至 4 万 Token。研究关注短暂流量突发为什么会引发远超突发持续时间的吞吐退化。

**核心机制。** 作者将这种现象描述为 metastability：流量突发导致服务变慢，系统中同时存活的会话增多，KV 工作集超过缓存容量，命中率下降后重算量进一步增大，最终形成自我强化的排队与缓存压力循环。这不是简单的“缓存容量不足”，而是请求驻留时间、会话工作集和服务速率耦合造成的状态转移。

**实验与证据。** 在同一基础负载的配对试验中，突发组有 12 对中的 9 对进入退化状态，出现约 10% 的命中率、约一半吞吐，并在后续 70 分钟持续积压；对照组没有对应的反向现象。作者还报告在 Qwen3-32B、SWE-bench 风格 Agent Trace 和 SGLang 上观察到类似现象。仅限制新请求准入，在 7 次匹配崩溃试验中只恢复 1 次；根据容量限制暂停已经准入的会话则全部在数分钟内恢复。CPU Offload 可以推迟退化，但不能在这些试验中根除它。

**限制与意义。** 结论来自作者选定的负载、缓存预算及引擎设置，不意味着任何 Agent 服务都必然出现同样的相变。它提醒系统设计者：优化平均 Prefix Hit Rate 不够，还要监控活动会话的 KV 工作集、尾部排队、恢复时间以及在扰动后的稳定性。对 Agent Serving 而言，缓存策略与准入/暂停策略必须协同设计。

### 3. WikiTrace：可回溯证据的 Agent 记忆

**来源与时间：** Yukyeong Lee 等，2026-11-10 首次提交；论文注明处于 ACL Rolling Review 审稿中，并非已录用；[论文](https://arxiv.org/abs/2611.14320)、[官方代码](https://github.com/yukyeongleee/wikitrace)。

**解决的问题。** 许多 Agent Memory 系统将历史轨迹压缩成简短的“经验教训”，但压缩过程可能产生错误归纳，或在新任务中错误套用。结果是 Agent 使用记忆反而失败，而不用记忆时可以成功，即 memory-induced degradation。

**核心机制。** WikiTrace 为每条 insight 保留与成功/失败解释摘要、原始执行轨迹的链接。Agent 在经验信息不足、不同经验互相冲突或经验源于失败任务时，通过终端工具向下追溯证据。其关键并非增加检索条数，而是把经验、证据和可验证执行记录构成分层访问结构。

**实验与证据。** 论文在五类 Agent Benchmark 上进行验证；官方仓库进一步列出八个测试 Suite，报告相对既有最佳记忆方法平均提升 8.5 个百分点，并给出 4.5% 的 Regression 指标。代码公开，提供构建记忆、运行测试与分析的命令，且区分 Gain（无记忆失败、有记忆成功）和 Regression（无记忆成功、有记忆失败）。

**限制与意义。** 保留原始轨迹增加存储空间与回溯 I/O；什么时候追溯、追溯多少、证据是否可信仍有成本与安全权衡。对于 Agent 基础设施，记忆需要 provenance、版本关联和审计接口，而不仅是向量相似度搜索。仓库已公开不等于本文所有实验都经过独立复现。

### 4. CAMP-II：用原生文件操作训练长程 Agent 记忆行为

**来源与时间：** Lirui Luo 等，2026-11-10 首次提交，2026-11-12 更新 v2；[论文原文](https://arxiv.org/abs/2611.14009)。

**解决的问题。** 长程任务超过模型有效上下文后，Agent 必须决定什么时候写入、更新、搜索和重新读取外部记忆。许多记忆训练方案设计了额外工具与压缩协议，但教师模型可能没有使用过这些接口，导致蒸馏信号弱、学生难以采样有效记忆动作。

**核心机制。** 作者提出 CAMG-II，覆盖 Shop、Coding、AutoResearch、General、Visual 五类长程环境；每个环境提供普通 Bash 操作和跨上下文替换持续存在的工作区。CAMP-II 以冻结教师模型为指导，通过完全异步的 on-policy distillation 在多个环境上联合训练单一策略，使写文件、修改文件、搜索文件和重新使用文件成为策略行为的一部分。

**实验与证据。** 论文报告在 CAMG-II 上获得最强 OPD 基线 2.97 倍的增益，并在 Terminal-Bench 2.1 与 SWE-Bench Pro V2 两个外部 Benchmark 上显示成功率改善。这里的“2.97 倍”是作者定义的**相对增益**，不是推理吞吐提升。v2 更新时间已由 arXiv 版本记录确认；未把版本更新本身推断为新实验结论。

**限制与意义。** 训练开销、跨模型泛化、文件系统读写量、工具调用延迟及长时间工作区清理仍需评估。更重要的是，记忆管理可以从 Prompt 工程演化为策略学习问题，而底层文件系统的命名、持久化、权限和检索性能会直接影响策略的可用动作空间。

## 开源项目的重要新闻

### WikiTrace 公开可运行的记忆评测与证据回溯实现

与上述论文配套的 [WikiTrace GitHub 仓库](https://github.com/yukyeongleee/wikitrace) 提供 Apache-2.0 许可的实现，包含记忆构建、Benchmark 运行和 Gain/Regression 分析流程。运行环境要求 Python 3.11+、Node 20、Docker 和 uv，示例沙箱采用无网络执行模式。其工程意义是让“记忆导致性能回退”从定性案例变成可以逐样本统计的指标，并允许按原始轨迹追查原因。

**状态与限制：** 已公开源码与安装说明，但没有在本期核实到 11 月 16 日当天的独立新 Release；这里记录的是近七日论文对应的开源实现，而非声称今日发布的新版本。对于 vLLM、SGLang、TensorRT-LLM 等项目，本期未找到足以核实发布日期、变更路径与合并状态的当天重要 PR，因此不把仓库历史 Release 页面中的累计特性误写为今日新闻。

## 前沿概念和技术

### 跨模型 KV 翻译与跨实例 KV 迁移的边界

传统 KV Transfer 假设生产者和消费者共享可解释的缓存布局及模型语义；BridgeKV 则使用可训练的映射来改变表示空间。两者解决的瓶颈不同：前者减少重复计算或设备间状态搬运，后者试图改变 Decode 所使用的模型计算成本。由此可以推测，未来缓存接口可能需要显式标注模型身份、层布局、量化格式与转换版本，避免把“可传输”误认为“可复用”。

### Agent Serving 的 Metastability 与记忆 Regression

Metastability 在这里指系统遭受短暂扰动后无法自动回到原先稳定工作区间；它强调的是动态恢复能力，而不只是某个时刻的吞吐。Memory Regression 则关注使用外部记忆后从成功变为失败的任务比例。前者是服务系统稳定性指标，后者是 Agent 行为质量指标。两篇研究共同说明：对有状态工作负载，平均命中率和平均成功率无法完整描述系统可靠性。

## 深度分析

上述研究揭示了两类不同的状态成本：推理时的缓存驻留与转换成本，以及 Agent 长程运行中的记忆验证和持久化成本。它们需要分别评估性能、质量与恢复能力，不能仅用单一命中率衡量。

## 对大模型推理与存储优化的启发

**第一，缓存容量管理需要纳入会话级预算。** Agent 多轮会话的活跃工作集随时间变化；仅以 Token 数量或请求到达率估计资源压力，可能遗漏会话驻留时间引起的正反馈。可考虑把 Prefix 命中、活动会话的预期 KV 需求与暂停恢复成本共同纳入服务控制面，但具体策略仍需独立验证。

**第二，KV Cache 的“身份”正在从地址扩展到语义兼容性。** 当 Prefill 与 Decode 使用不同模型时，缓存能否复用不再仅由哈希与块地址决定，还取决于转换模块、模型版本和质量容忍度。缓存管理与模型执行计划之间的接口可能进一步耦合。

**第三，Agent 记忆存储应同时支持压缩访问与证据回溯。** WikiTrace 的设计说明高频读取的精炼 insight 与低频访问的原始轨迹可以采用不同访问路径。其潜在收益依赖实际回溯频率、原始轨迹大小、读取延迟及隔离要求，不能简单等同于“分层存储必然加速”。

**第四，文件系统操作成为 Agent 训练与推理接口。** CAMP-II 表明文件的创建、修改和查询可以进入训练闭环。这要求系统研究不仅测量静态检索准确率，也测量上下文替换后的工作区持久性、文件修改冲突、恢复成本和端到端工具调用开销。

## 今夜白的观察

本期四篇论文从不同角度指向同一个系统趋势：**推理与 Agent 的关键状态不再是执行过程的被动副产物，而正在成为可转换、可调度、可验证、可学习管理的对象。** BridgeKV 讨论状态表示能否跨模型转换；Agent Prefix Cache 研究揭示状态驻留与系统稳定性的关系；WikiTrace 要求状态附带可追溯证据；CAMP-II 则把状态读写纳入模型策略。

这并不意味着这些机制已经可以直接组合成统一运行时。跨模型 KV 的精度损失、缓存失稳的负载边界、证据回溯的 I/O 成本以及文件操作策略的泛化能力，仍分别缺少跨平台、跨工作负载的充分验证。后续值得跟踪的是：是否出现统一的状态生命周期评测、Agent 工作负载公开 Trace，以及能够同时衡量服务稳定性、记忆 Regression 和状态恢复开销的系统基准。
