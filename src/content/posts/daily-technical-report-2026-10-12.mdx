# 每日技术报告｜2026-10-12

## 今日概览

本期以 10 月 8—9 日首次提交的 arXiv 论文为主体，补充 10 月 12 日的工程更新；不将周末后出现在 recent 列表的论文误写成今天首次发表。

- GraphTok 揭示 Agent 长上下文即使命中 prefix cache，CPU 分词仍可能主导 TTFT。
- CompileMask 把动态注意力可见性规则编译为低成本执行描述符，ReadKV 则把 KV 存储预算和单次读取预算分离。
- Ember 使用热区计数器管理 GPU 超订内存，ByteExpress 把 RDMA 的缓冲、背压与恢复视为一个整体。
- Humanize MLE Agents 通过跨会话交替处理长程 Agent 的执行衰减；RATED 将工具可靠性纳入检索。
- vLLM 新 PR 补齐 Qwen3.5 跨流水线的推测解码辅助状态；最新 H100 复测显示内核优化必须看端到端。

## 重点进展：核心论文与技术报告

### GraphTok：前缀命中后，分词仍可能是最大开销

Mohammad Siavashi 等 10 月 9 日发布 [Taking Tokenization off the Host for Agentic LLM Serving](https://arxiv.org/abs/2610.13325)。论文观察到 Agent 反复发送大部分相同的长 prompt：GPU 前缀缓存可跳过 prefill，但查询缓存之前仍需重新 tokenization。GraphTok 将预分词、BPE 合并和 token ID 组装封装进 CUDA Graph，并在短输入时使用 CPU 回退。作者报告百万 GPT-2 token 编码含传输为 1.7—3.2 ms；Llama 3 上比 gigatoken 快 4.7—6.0 倍；vLLM 缓存命中场景平均 TTFT 改善 2.1—2.4 倍。一个 Dynamo 前端在 121K-token 请求、2 秒 P99 目标下处理 518 req/s，超过 gigatoken 的 296 req/s。限制是收益高度依赖重复长输入和前缀命中，不可外推至短请求；论文页面未明确提供可核验的代码链接。

### CompileMask：编译动态 Attention Mask

Hongzheng Li 等 10 月 9 日提交 [CompileMask](https://arxiv.org/abs/2610.13474)。现有 predicate mask 表达灵活却增加预处理开销，固定区间方案则限制规则形态。作者提出 MaskSpec 区域 DSL，离线分析可见性规则并生成专用预处理 kernel，在线根据 batch 元数据生成紧凑 Execution Descriptor；attention kernel 仅需比较预计算端点。论文报告最高 3.8 倍局部加速，但这不是全链路 LLM serving 加速。值得关注的是将动态 mask 的表达与执行分离；仍需评估编译缓存和在线描述符构造成本。

### ReadKV：保留的精度不等于每次读取的精度

Siddharth Bhandari 等 10 月 8 日提交 [Read What Matters](https://arxiv.org/abs/2610.11245)。它将 KV 写成可逐级重构的编码，先根据 query 决定读取哪些 key-channel 比特，再根据估计 attention 决定读取哪些 value-token 比特，不必重写原 KV。作者在六个基础模型上报告：8-bit 缓存平均读取 4 bit 时，C4 perplexity 增幅最多 0.66%。在 A10G、8K、batch 1、单层条件下，受限 2-bit 读取方案比测试的 TurboQuant codec 延迟低 39%。该结果不能解释为完整推理系统快 39%；其研究价值在于把容量、读取带宽与质量约束拆成不同维度。

### Ember：用热度反馈替代纯缺页迁移

Senad-Leandro Lemes Galera 等 10 月 9 日提交 [Ember](https://arxiv.org/abs/2610.13408)。传统 UVM 在 GPU 内存超订时按 fault 迁移数据，可能造成互连浪费。Ember 让初始分配映射主机内存，用 GPU 硬件计数器识别热区并晋升，按衰减信号批量回收冷区；同时提供驱动实现和 stock CUDA 用户态变体。作者在三种 PCIe GPU、六个应用的 1.5 倍超订场景报告相对 UVM 6.8—10.6 倍提升。对 LLM 的价值是工作集在线迁移，但不能将相对退化 UVM 的倍数理解为超过 HBM 常驻部署。

### Humanize MLE Agents：跨会话重置而不是无限压缩上下文

Changye Li 等 10 月 9 日提交 [Humanize MLE Agents](https://arxiv.org/abs/2610.13494)，并公开 [实验代码](https://github.com/humanfia/hma)。论文将长会话推理强度下降和定制 harness 随模型更新失效视为两类问题。HMA 让两个 Agent 交替使用同一工作区，每段 session 限制实验次数并重置上下文，用 context-reset semi-Markov 模型讨论何时交替有利。75 个 MLE-bench Kaggle 任务上，作者报告 any-medal rate 78.2%，高于最强开源对照 8 个百分点，且使用其四分之一的时间预算。其收益需要可交接的实验产物，不能直接泛化至所有 Agent 任务。

### RATED：工具检索需要感知实时故障

Weiliang Chen 与 Song Liao 10 月 9 日提交 [RATED](https://arxiv.org/abs/2610.13889)，论文注明 CIKM 2026，提供 [代码和 EcoAgent 数据](https://github.com/Elliotes/EcoAgent)。RATED 使用语义双编码器生成候选，再用 contextual bandit 根据 API 执行反馈重排。作者报告 EcoAgent 包含 5,172 个工具和超过 21 万查询—工具对；相对 ToolLLM API retriever，MRR 相对提高 52.2%；设定 30% 故障率时，故障工具选择率从 86.2% 降到 2.9%。限制是仿真故障与真实鉴权、限流和语义错误不完全等价，但方法明确提出了动态可靠性这一 Agent 检索信号。

### ByteExpress：生产 RDMA 的控制面同样重要

Yibo Huang 等 10 月 8 日提交 [Deploying RDMA for Large-Scale Inference and Training Workloads](https://arxiv.org/abs/2610.12815)。论文总结字节跳动参数服务器型推理和训练的 RDMA 部署经验：RDMA-aware allocator、零拷贝、QP multiplexing、接收 credit、发送窗口与 RPC 辅助恢复共同处理连接规模、incast 与失败。相对 kernel TCP，作者报告生产推理参数获取平均延迟降低 35.7%、P99 降低 43.7%，CPU 用量降低 10.69%。这不是 KV offload 的直接 benchmark，但说明高性能数据移动必须同时解决缓冲生命周期、流控和可恢复性。

## 深度分析

本期有两条贯穿系统设计的线索。第一，优化边界向请求准备阶段外移：GraphTok 说明缓存命中后 CPU tokenization 可以主导 TTFT，故端到端 profile 必须包含前端编码、缓存查询、数据恢复、prefill 和 decode。第二，状态管理从“保留或驱逐”扩展为多个正交决策：ReadKV 控制每次读取的精度，Ember 控制区域何时驻留，CompileMask 控制访问模式如何表达。它们各自优化不同成本，论文间加速比不能相乘。

## 开源项目的重要新闻

**vLLM Qwen3.5 推测解码：** 10 月 12 日创建的 [PR #61180](https://github.com/vllm-project/vllm/pull/61180) 仍为 Open、未合并。它在 PP stages 之间传递 EAGLE3/DFlash 辅助 hidden states，按全局层顺序打包和收集，并补齐缺失 slot 检查。作者报告 15 个定向测试通过；问题报告者在异构 PP2 上验证了相同生产改动的 rebase 前版本，930 个草拟 token 接受 238 个。验证不等于最终 PR 已发布。

**vLLM Triton tile64：** [Issue #61029](https://github.com/vllm-project/vllm/issues/61029) 10 月 12 日新增 H100 连续批处理复测。最新六组完整实验中，64-token tile 相对现有 Triton 在并发 1/4 时吞吐改善约 3.0%/2.8%，并发 8/16 时约 0.6%/0.5%，高并发基本无收益。作者指出 CUDA Graph capture 的 guard 使用 max_model_len 而非实际请求长度。当前仅是开放讨论和实验 patch，未合并为默认配置。

## 前沿概念和技术

**Query-adaptive reading** 是 ReadKV 的按 query 选择读取精度，而不是固定低比特量化。**Context-reset scheduling** 则由 HMA 体现：把上下文重置、交接和共享工作区纳入任务执行策略，而非不断扩张单一会话。两者都提示：系统状态的生命周期和访问需求不必保持一致。

## 对大模型推理与存储优化的启发

KV 性能评价应区分显存容量、读取字节数、元数据开销与访问形态，并在相同模型质量和 SLO 下测试；Agent serving 还需要考虑反复 tokenization、工具故障、session gap 与 workspace 持久化。Ember 的区域迁移与 ReadKV 的精度读取可能形成互补，但这只是推断，尚无本文所引论文证明其组合收益。

## 今夜白的观察

这批工作说明，未来的系统收益可能越来越来自跨边界优化：CPU 前端与 GPU、mask 规则与执行 kernel、KV 存储与查询读取、Agent 会话与持久工作区。不过，GraphTok 的长前缀负载、ReadKV 的单层实验、Ember 的超订 UVM、HMA 的 Kaggle 任务各有特殊假设。值得继续跟踪的是在统一真实工作负载、明确质量约束和端到端尾延迟下，这些机制还能保留多少收益。
